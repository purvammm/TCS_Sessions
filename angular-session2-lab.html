① Import FormsModule — the step everyone forgets

📄src/app/app.module.tsREPLACE the whole file
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms';        // ① import it

import { AppComponent } from './app.component';
import { HeaderComponent } from './header/header.component';
import { EmployeeListComponent } from './employee-list/employee-list.component';
import { LoginComponent } from './login/login.component';

@NgModule({
  declarations: [
    AppComponent,
    HeaderComponent,
    EmployeeListComponent,
    LoginComponent
  ],
  imports: [
    BrowserModule,
    FormsModule                                      // ② list it here
  ],
  providers: [],
  bootstrap: [AppComponent]
})
export class AppModule { }
Both lines are required The import at the top makes the name available to this file. Adding FormsModule to the imports array is what actually switches on ngModel for your templates. One without the other does nothing.

② The login component class

📄src/app/login/login.component.tsREPLACE the whole file
import { Component } from '@angular/core';

@Component({
  selector: 'app-login',
  templateUrl: './login.component.html',
  styleUrls: ['./login.component.css']
})
export class LoginComponent {

  uname: string = '';
  pass: string = '';
  message: string = '';
  isSuccess: boolean = false;

  performLogin(): void {
    if (this.uname === 'admin' && this.pass === 'admin123') {
      this.isSuccess = true;
      this.message = 'Login successful. Welcome, ' + this.uname + '!';
    } else {
      this.isSuccess = false;
      this.message = 'Invalid username or password.';
    }
  }

  reset(): void {
    this.uname = '';
    this.pass = '';
    this.message = '';
  }
}

TASK 4▶ Conditional Styling — *ngIf + ngClassTheory slides 21, 25–26
Goal Make the table react to its data: green rows for Active employees, red for Inactive, and a friendly "no employees" message when the list is empty. Two directives, a real visual result.
Do this — step by step
  1. Add a clearAll() method and a reload() method to the component so you can empty the array on demand and watch *ngIf switch over.
  2. Wrap the table in *ngIf with an else branch.
  3. Add [ngClass] to the <tr> and define the two classes in the CSS.

① Add the two methods

📄src/app/employee-list/employee-list.component.tsREPLACE the whole file
import { Component } from '@angular/core';
import { Employee } from '../models/employee';

@Component({
  selector: 'app-employee-list',
  templateUrl: './employee-list.component.html',
  styleUrls: ['./employee-list.component.css']
})
export class EmployeeListComponent {

  employees: Employee[] = [];

  constructor() {
    this.reload();
  }

  reload(): void {
    this.employees = [
      { id: 1001, name: 'Anoop',  designation: 'Software Engineer', salary: 25000, status: 'Active',   joinDate: new Date('2022-08-15') },
      { id: 1002, name: 'Ajay',   designation: 'Team Lead',         salary: 45000, status: 'Inactive', joinDate: new Date('2019-03-01') },
      { id: 1003, name: 'Rekha',  designation: 'Tester',            salary: 22000, status: 'Active',   joinDate: new Date('2023-01-10') },
      { id: 1004, name: 'Suresh', designation: 'Architect',         salary: 65000, status: 'Inactive', joinDate: new Date('2015-11-23') }
    ];
  }

  clearAll(): void {
    this.employees = [];
  }

  toggleStatus(emp: Employee): void {
    emp.status = emp.status === 'Active' ? 'Inactive' : 'Active';
  }
}
Why move the data into a method? Two reasons. First, you can now empty and restore the list at will to test *ngIf. Second — and this is the real point — this is the exact shape Session 3 refactors: that reload() body becomes a call to employeeService.getEmployees(). You're already writing code that's ready for a service.

The crucial thing to verify Look back at your .ts file: name is still 'Anoop', not 'ANOOP'. salary is still the number 25000, so you can still do arithmetic on it. A pipe changes the display, never the data. That's precisely why you'd never do this by mutating the property.
Try the debugging pipe — worth remembering forever Add this line anywhere in the template:

Your entire array prints as formatted JSON on the page. When something isn't rendering and you can't see why, | json answers "what is actually in this variable?" faster than anything else. You will use this constantly in Session 3 when API responses aren't the shape you expected.

import { Component } from '@angular/core';

@Component({
  selector: 'app-day-badge',
  templateUrl: './day-badge.component.html',
  styleUrls: ['./day-badge.component.css']

export class DayBadgeComponent {

  // 0 = Sunday ... 6 = Saturday
  dayNumber: number = new Date().getDay();

  next(): void {
    this.dayNumber = (this.dayNumber + 1) % 7;
  }
}

SelectorThe custom tag that renders a component, e.g. <app-login>
