Part 2 — Data binding
TASK 2▶ Binding Playground — Interpolation & Property BindingTheory slides 16–19
Goal Get both class → template bindings working before we add events. This is a deliberately small, safe task whose real purpose is to make the difference between {{ }} and [ ] permanent — because mixing them up is the most common Session 2 confusion.
📄 src/app/header/header.component.ts Replace the whole file 
import { Component } from '@angular/core';

@Component({
  selector: 'app-header',
  templateUrl: './header.component.html',
  styleUrls: ['./header.component.css']
})
export class HeaderComponent {
  // ── plain fields, for interpolation ──
  portalName = 'Employee Portal';
  version = 2;
  employeeCount = 4;

  // ── values used with property binding ──
  docsUrl = 'https://angular.dev';
  isMaintenanceMode = false;

  // ── a method the template can call ──
  getSubtitle(): string {
    return 'Session ' + this.version + ' — Components & Data Binding';
  }
}
Keep the @Component block your CLI generated If yours says styleUrl (singular, no array), or includes standalone: true and an imports: [] line, leave those lines exactly as they are and change only the class body underneath. This applies to every file in today's lab.

  2. Misspell a field: change {{ portalName }} to {{ portalname }} (lower-case n). Save. The text simply disappears — no error anywhere. This is the silent bug to remember. Fix it.

  4. Try something illegal: {{ employeeCount = 10 }}. The build fails, because a template expression may read but never assign. Remove it.

Step 3 — the full login component

📄 src/app/login/login.component.ts Replace the whole file 
import { Component } from '@angular/core';

@Component({
  selector: 'app-login',
  templateUrl: './login.component.html',
  styleUrls: ['./login.component.css']
})
export class LoginComponent {

  // Two-way bound to the two inputs
  username = '';
  password = '';

  // Set by the buttons, displayed by interpolation
  message = '';
  isSuccess = false;
  attempts = 0;

  onLogin(): void {
    this.attempts++;

    if (this.username === 'admin' && this.password === 'admin123') {
      this.message = '✅ Login successful! Welcome, ' + this.username + '.';
      this.isSuccess = true;
    } else {
      this.message = '❌ Invalid credentials. Try admin / admin123.';
      this.isSuccess = false;
    }
  }

  onClear(): void {
    this.username = '';
    this.password = '';
    this.message = '';
    this.isSuccess = false;
  }
}

export class EmployeeListComponent {

    { id: 1001, name: 'anoop kumar',  designation: 'Software Engineer', salary: 25000, status: 'Active',   email: 'anoop@example.com' },

Part of the *ngForWhat it means
*ngForThe asterisk marks it structural — it adds and removes elements. Forget the asterisk and nothing happens, silently.
let empA name you invent for the current item. It only exists inside this <tr>.
of employeesThe array on your class. It is of, never in — same as for...of in TypeScript.
; let i = indexNote the semicolon. Gives you the position, starting at 0 — which is why the template prints i + 1.
; trackBy: trackByIdTells Angular to identify rows by id instead of rebuilding them all. A good habit; essential on large tables.

TASK 5▶ Conditional Display & Styling — *ngIf, ngClass, ngStyleTheory slides 27–28, 32–34
Goal Make the table react to its own data: green rows for Active employees, red for Inactive, bold salaries for high earners, a working Show/Hide toggle, a live search box, and a sensible "nothing found" message. Everything here is driven by data — you will not write a single line that manipulates the page directly.
📄 src/app/employee-list/employee-list.component.ts Replace the whole file 
import { Component } from '@angular/core';
import { Employee } from '../models/employee';

@Component({
  selector: 'app-employee-list',
  templateUrl: './employee-list.component.html',
  styleUrls: ['./employee-list.component.css']
})
export class EmployeeListComponent {

  heading = 'Employee Directory';

  // controls the Show / Hide toggle
  showTable = true;

  // two-way bound to the search box
  searchTerm = '';

  allEmployees: Employee[] = [
    { id: 1001, name: 'anoop kumar',  designation: 'Software Engineer', salary: 25000, status: 'Active',   email: 'anoop@example.com' },
    { id: 1002, name: 'ajay sharma',  designation: 'Team Lead',         salary: 45000, status: 'Inactive' },
    { id: 1003, name: 'rekha nair',   designation: 'Tester',            salary: 22000, status: 'Active',   email: 'rekha@example.com' },
    { id: 1004, name: 'suresh patel', designation: 'Architect',         salary: 65000, status: 'Inactive' }
  ];

  // What the table actually displays. Starts as everything.
  employees: Employee[] = this.allEmployees;

  toggleTable(): void {
    this.showTable = !this.showTable;
  }

  // Called on every keystroke in the search box
  onSearch(): void {
    const term = this.searchTerm.trim().toLowerCase();

    if (term === '') {
      this.employees = this.allEmployees;
      return;
    }

    this.employees = this.allEmployees.filter(e =>
      e.name.toLowerCase().includes(term) ||
      e.designation.toLowerCase().includes(term)
    );
  }

  getActiveCount(): number {
    return this.employees.filter(e => e.status === 'Active').length;
  }

  trackById(index: number, emp: Employee): number {
    return emp.id;
  }
}
Design decisionWhy it's done this way
allEmployees + employeesTwo arrays. allEmployees is the full, untouched list; employees is what's on screen. Without this split, searching would permanently destroy rows and clearing the box could not bring them back.
.trim().toLowerCase()Makes the search forgiving — stray spaces and any capitalisation still match. Small touch, big difference to how the app feels.
filter(...)Returns a new array and leaves the original alone. This is exactly Drill H from Session 1's lab.
|| (or)Matches on name or designation, so typing "lead" finds Ajay.

TASK 7▶ A Reusable Card with @Input and @OutputTheory slides 38–41
Goal Build a small employee-card component that knows nothing about where its data comes from. The parent hands it one employee (@Input), and when its Delete button is pressed the card reports that upward (@Output) and lets the parent decide what to do. This is the data down, events up pattern, and it is what makes components genuinely reusable.

Step 1 — generate the card

ng g c employee-card

Step 2 — the child: declare what it accepts and what it announces

📄 src/app/employee-card/employee-card.component.ts Replace the whole file 
import { Component, Input, Output, EventEmitter, OnInit } from '@angular/core';
import { Employee } from '../models/employee';

@Component({
  selector: 'app-employee-card',
  templateUrl: './employee-card.component.html',
  styleUrls: ['./employee-card.component.css']
})
export class EmployeeCardComponent implements OnInit {

  // ── @Input: values the PARENT passes DOWN to me ──
  @Input() employee!: Employee;
  @Input() showSalary = true;

  // ── @Output: events I send UP to my parent ──
  @Output() deleteRequested = new EventEmitter<number>();
  @Output() cardSelected = new EventEmitter<Employee>();

  initials = '';

  ngOnInit(): void {
    // Safe to read @Input values HERE — they have arrived by now.
    // Reading them in the constructor would crash: they'd still be undefined.
    this.initials = this.employee.name
      .split(' ')
      .map(part => part.charAt(0).toUpperCase())
      .join('');
  }

  onDeleteClick(): void {
    // I don't delete anything. I just announce that someone asked.
    this.deleteRequested.emit(this.employee.id);
  }

  onCardClick(): void {
    this.cardSelected.emit(this.employee);
  }
}
LineWhat it does, and why it's written that way
@Input() employee!: Employee;Declares an input. The ! tells strict mode "a parent will definitely set this" — without it you get "has no initializer and is not definitely assigned".
@Input() showSalary = true;An input with a default, so the parent may leave it out. No ! needed, because it already has a value.
@Output() deleteRequested = new EventEmitter<number>();Declares a custom event. The <number> says "I will emit a number" — here, the employee's id. TypeScript then checks the parent's handler accepts a number.
.emit(this.employee.id)Fires the event, carrying the id. The parent receives it as $event.
ngOnInit() { ... }The critical placement. @Input values are set after the constructor runs. Computing initials in the constructor would throw "Cannot read properties of undefined". This is exactly why ngOnInit exists.

▶ Troubleshooting — organised by symptomTheory slide 42
Read this first Most Session 2 bugs are silent — no red text anywhere, the page just doesn't behave. So the table below is organised by what you observe, not by error message. Scan the left column for what you are seeing.
What you observeCause and fix
Can't bind to 'ngModel' since it isn't a known property of 'input' The Session 2 error. Add import { FormsModule } from '@angular/forms'; and put FormsModule in the imports array of app.module.ts. Remember: "can't bind to X" = a module is missing.
'app-employee-card' is not a known element Three possibilities, check in order: (a) not in declarations, (b) the tag doesn't match the selector, (c) you created the files by hand instead of with ng g c.
A child component renders nothing, no error You wrote <app-card />. Angular components need an explicit closing tag: <app-card></app-card>. Fails completely silently.
A section refuses to hide Missing asterisk — ngIf instead of *ngIf. Angular treats it as a meaningless attribute and shows the element always. No error.
The table body is empty but the array has data *ngFor="let e in list". It must be of, not in. Silent.
Four whole tables instead of four rows The *ngFor is on <table>. Move it to <tr> — the asterisk goes on the single tag you want copies of.
{{ something }} shows nothing at all A spelling or capitalisation mismatch between template and class. Angular renders missing fields as an empty string with no warning. Check both very carefully.
A button does nothing when clicked (click)="onSave" — missing (), so you named the method instead of calling it. Should be (click)="onSave()".
A link or image points at a literal field name Brackets missing: href="docsUrl" instead of [href]="docsUrl". Without brackets the right-hand side is a plain string, not an expression.
A button stays disabled forever disabled="false" — the string "false" is non-empty, and HTML reads any value as "yes". Use [disabled]="false". Same trap applies to @Input booleans.
*ngSwitchCase never matches Missing inner quotes. Must be *ngSwitchCase="'Tester'" — double outside, single inside.
Cannot read properties of undefined (reading 'name') in a child You used an @Input value in the constructor. Inputs arrive after construction — move the code into ngOnInit.
Property 'employee' has no initializer and is not definitely assigned Strict mode. Add the !: @Input() employee!: Employee; — meaning "a parent will set this".
The pipe 'titlcase' could not be found A misspelled pipe name. Helpfully, this one does report itself. Check the spelling.
Row colours don't change Usually the CSS class names in [ngClass] don't match the ones in your .css file — or the condition is never true. Add {{ emp.status }} next to it temporarily to see the real value.
Deleted a card, but the table row is still there You filtered only one of the two arrays. Remove the item from allEmployees and employees.
Clearing the search box doesn't bring rows back You filtered allEmployees itself instead of assigning the result to employees. The full list must stay untouched.
Clicking ✕ also selects the card The click "bubbles" up to the card's own handler. Add $event.stopPropagation() to the button's click, as shown in Task 7.
▶ Glossary — Session 2 terms
TermMeaning in one sentence
ComponentOne self-contained piece of screen: a class, a template, scoped styles, and a @Component decorator.
TemplateThe HTML belonging to a component.
SelectorThe custom tag name that renders a component, e.g. <app-header>.
Component treeThe nesting of components, with AppComponent always at the top.
View encapsulationAngular scoping a component's CSS so it cannot affect anything outside that component.
Data bindingThe live connection between a component class and its template.
Interpolation{{ value }} — display a value as text. Class → template.
Property binding[attr]="value" — set an element's property from your data. Class → template.
Event binding(click)="method()" — run a method when something happens. Template → class.
Two-way binding[(ngModel)]="field" — keep an input and a field in step, both ways. "Banana in a box".
$eventThe event object Angular passes into an event binding — or the emitted value, for a custom @Output.
Template expressionThe code inside a binding. It must produce a value and must not change anything.
DirectiveAn instruction attached to an element that changes its behaviour or appearance.
Structural directiveAdds or removes elements. Always written with a leading asterisk: *ngIf, *ngFor, *ngSwitchCase.
Attribute directiveChanges an element that already exists. No asterisk: ngClass, ngStyle, ngModel.
*ngIfInclude the element only when the condition is true — it is genuinely removed, not hidden.
*ngForRepeat an element once per array item. Supports index, first, last, even, odd.
trackByTells *ngFor how to identify items so Angular reuses rows instead of rebuilding them all.
ng-templateA container that renders nothing itself — it holds markup for something else, such as an *ngIf else branch.
Pipe{{ value | pipeName }} — formats a value for display only, leaving the data unchanged.
Chaining pipesFeeding one pipe's output into the next: {{ d | date:'fullDate' | uppercase }}.
@InputA property a parent may set on a child. Data flows down.
@OutputA custom event a child raises for its parent, using an EventEmitter. Events flow up.
EventEmitterThe object an @Output uses; you call .emit(value) on it.
Data down, events upThe convention that parents pass data to children and children report events back, never the reverse.
Lifecycle hookA method Angular calls at a known moment in a component's life.
ngOnInitRuns once, after construction and after @Input values arrive. Where setup code belongs.
FormsModuleThe Angular module that provides ngModel. Must be in imports.
