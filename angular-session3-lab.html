Today's golden rule No subscribe, no request. Observables are lazy — if you call an HTTP method and never subscribe, absolutely nothing happens: no network traffic, no error, no warning. import { Component } from '@angular/core';

@Component({
  selector: 'app-employee-form-td',
  templateUrl: './employee-form-td.component.html',
  styleUrls: ['./employee-form-td.component.css']
})
export class EmployeeFormTdComponent {

  // ONE object holding the whole form. Each field two-way binds to a property.
  employee = {
    name: '',
    email: '',
    salary: 0,
    designation: 'Software Engineer'
  };

  designations = ['Software Engineer', 'Team Lead', 'Tester', 'Architect'];

  submitted = false;
  savedData = '';

  onSubmit(): void {
    this.submitted = true;
    this.savedData = JSON.stringify(this.employee, null, 2);
    console.log('Template-driven form submitted:', this.employee);
  }

  onReset(): void {
    this.employee = { name: '', email: '', salary: 0, designation: 'Software Engineer' };
    this.submitted = false;
    this.savedData = '';
  }
}

import { Component } from '@angular/core';
import { FormGroup, FormControl } from '@angular/forms';

@Component({
  selector: 'app-employee-form-rx',
  templateUrl: './employee-form-rx.component.html',
  styleUrls: ['./employee-form-rx.component.css']
})
export class EmployeeFormRxComponent {

  designations = ['Software Engineer', 'Team Lead', 'Tester', 'Architect'];

  submitted = false;
  savedData = '';

  // THE FORM IS AN OBJECT IN THE CLASS.
  // No validation yet — we add that in Task 3, deliberately.
  empForm = new FormGroup({
    name:        new FormControl(''),
    email:       new FormControl(''),
    salary:      new FormControl(0),
    designation: new FormControl('Software Engineer')
  });

  onSubmit(): void {
    this.submitted = true;
    this.savedData = JSON.stringify(this.empForm.value, null, 2);
    console.log('Reactive form submitted:', this.empForm.value);
  }

  onReset(): void {
    this.empForm.reset({ name: '', email: '', salary: 0, designation: 'Software Engineer' });
    this.submitted = false;
    this.savedData = '';
  }

  // Proof that you can drive the form from code — impossible to do this
  // cleanly in a template-driven form.
  fillSampleData(): void {
    this.empForm.patchValue({
      name: 'Anoop Kumar',
      email: 'anoop@example.com',
      salary: 25000,
      designation: 'Software Engineer'
    });
  }
}

TASK 3▶ Add Validation — Validators and FormBuilderTheory slides 13–15
Goal Bring the reactive form up to the same standard as the template-driven one — the same rules, the same polite error messages — but with every rule written in TypeScript. Then rewrite the whole thing using FormBuilder, which is what you will actually meet in real codebases.

Step 1 — add the validators

📄 src/app/employee-form-rx/employee-form-rx.component.ts Replace the whole file 
import { Component } from '@angular/core';
import { FormGroup, FormControl, Validators } from '@angular/forms';

@Component({
  selector: 'app-employee-form-rx',
  templateUrl: './employee-form-rx.component.html',
  styleUrls: ['./employee-form-rx.component.css']
})
export class EmployeeFormRxComponent {

  designations = ['Software Engineer', 'Team Lead', 'Tester', 'Architect'];

  submitted = false;
  savedData = '';

  empForm = new FormGroup({
    name: new FormControl('', [
      Validators.required,
      Validators.minLength(3),
      Validators.maxLength(30)
    ]),
    email: new FormControl('', [
      Validators.required,
      Validators.email
    ]),
    salary: new FormControl(0, [
      Validators.required,
      Validators.min(1000),
      Validators.max(500000)
    ]),
    designation: new FormControl('Software Engineer', [
      Validators.required
    ])
  });

  // ── GETTERS: make the template far easier to read ──
  get name()   { return this.empForm.get('name'); }
  get email()  { return this.empForm.get('email'); }
  get salary() { return this.empForm.get('salary'); }

  onSubmit(): void {
    if (this.empForm.invalid) {
      // Mark everything touched so ALL errors appear at once
      this.empForm.markAllAsTouched();
      return;
    }
    this.submitted = true;
    this.savedData = JSON.stringify(this.empForm.value, null, 2);
  }

  onReset(): void {
    this.empForm.reset({ name: '', email: '', salary: 0, designation: 'Software Engineer' });
    this.submitted = false;
    this.savedData = '';
  }

  fillSampleData(): void {
    this.empForm.patchValue({
      name: 'Anoop Kumar',
      email: 'anoop@example.com',
      salary: 25000
    });
  }
}
LineWhy it's there
Validators.requiredNo brackets — you are passing the function itself.
Validators.minLength(3)With brackets — you are calling it to build a function. Note the capital L, unlike the HTML attribute.
get name() { ... }A TypeScript getter, so the template can write name?.errors instead of empForm.get('name')?.errors. Purely for readability, and worth it.
markAllAsTouched()If someone submits an untouched invalid form, this reveals every error at once instead of leaving them guessing what's wrong.

Step 3 — the same form again, with FormBuilder

This is the version you will meet in real projects. Replace only the imports, the empForm declaration and the constructor:

📄 src/app/employee-form-rx/employee-form-rx.component.ts Swap these parts in 
import { Component } from '@angular/core';
import { FormBuilder, FormGroup, Validators } from '@angular/forms';

// ...inside the class, REPLACE the empForm = new FormGroup({...}) block with:

  empForm: FormGroup;

  constructor(private fb: FormBuilder) {
    this.empForm = this.fb.group({
      name:        ['', [Validators.required, Validators.minLength(3), Validators.maxLength(30)]],
      email:       ['', [Validators.required, Validators.email]],
      salary:      [0,  [Validators.required, Validators.min(1000), Validators.max(500000)]],
      designation: ['Software Engineer', [Validators.required]]
    });
  }

// Everything else in the class stays exactly the same.
How to read the shorthand Each field is an array of two things: fieldName: [ startingValue, [validators] ]. That is the entire syntax.
What you should see Absolutely no change on screen. Same form, same validation, same behaviour — roughly forty percent less code. That is the whole reason FormBuilder exists.
Look at that constructor — you've now used dependency injection constructor(private fb: FormBuilder) { } is the exact shorthand from Session 1's Drill L. You asked for a FormBuilder and Angular created one and handed it to you — you never wrote new FormBuilder(). That is dependency injection, and Task 5 does the same thing with a service you wrote yourself. Note also that the form must be built inside the constructor, because this.fb does not exist until then.
Try it yourself — three things worth proving
  1. Click Save on a completely empty, untouched form. Every error appears at once — that is markAllAsTouched(). Comment that line out and try again: nothing appears, and the user has no idea why Save did nothing.
  2. Add a validator at runtime — something template-driven forms simply cannot do. In fillSampleData(), add: this.empForm.get('salary')?.addValidators(Validators.min(20000)); then this.empForm.get('salary')?.updateValueAndValidity();. The rules changed while the app was running.
  3. Watch a live stream of changes. Add this to the constructor, after building the form, then type in the Name box and watch the console: this.empForm.get('name')?.valueChanges.subscribe(v => console.log('name:', v)); That's an Observable — the same mechanism HttpClient uses in Task 6.

import { Injectable } from '@angular/core';
import { Employee } from '../models/employee';

@Injectable({
  providedIn: 'root'      // ← ONE instance, shared by the whole app
})
export class EmployeeService {

  // PRIVATE — the outside world can only reach this through my methods.
  private employees: Employee[] = [
    { id: 1001, name: 'anoop kumar',  designation: 'Software Engineer', salary: 25000, status: 'Active',   email: 'anoop@example.com' },
    { id: 1002, name: 'ajay sharma',  designation: 'Team Lead',         salary: 45000, status: 'Inactive' },
    { id: 1003, name: 'rekha nair',   designation: 'Tester',            salary: 22000, status: 'Active',   email: 'rekha@example.com' },
    { id: 1004, name: 'suresh patel', designation: 'Architect',         salary: 65000, status: 'Inactive' }
  ];

  // ── READ ────────────────────────────────────────────────
  getEmployees(): Employee[] {
    return this.employees;
  }

  getById(id: number): Employee | undefined {
    return this.employees.find(e => e.id === id);
  }

  // ── SEARCH ──────────────────────────────────────────────
  searchByName(term: string): Employee[] {
    const t = term.trim().toLowerCase();
    if (t === '') { return this.employees; }
    return this.employees.filter(e =>
      e.name.toLowerCase().includes(t) ||
      e.designation.toLowerCase().includes(t)
    );
  }

  // ── CREATE ──────────────────────────────────────────────
  addEmployee(emp: Employee): void {
    this.employees.push(emp);
  }

  // ── DELETE ──────────────────────────────────────────────
  deleteEmployee(id: number): void {
    const i = this.employees.findIndex(e => e.id === id);
    if (i !== -1) {
      this.employees.splice(i, 1);
    }
  }

  // ── a couple of derived values, also better here than in a component ──
  getActiveCount(): number {
    return this.employees.filter(e => e.status === 'Active').length;
  }

  getTotalSalary(): number {
    let total = 0;
    for (const e of this.employees) {
      total = total + e.salary;
    }
    return total;
  }
}
DecisionWhy
@Injectable({ providedIn: 'root' })Registers the service and makes it a singleton — every component that injects it gets the same instance, so they genuinely share data.
private employeesNothing outside can reassign or corrupt the array. Every access goes through a method you control — the same discipline as a private field with getters in Java.
The six array methodsfind, filter, push, findIndex, splice — exactly Drill H from Session 1's lab. This is now a complete in-memory CRUD layer.
getActiveCount / getTotalSalaryDerived data belongs with the data, not in a component. Now a dashboard can use them too.

// ── 1. ADD these imports at the top of the file ──
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';
import { map } from 'rxjs/operators';
import { ApiUser } from '../models/api-user';

// ── 2. ADD a constructor to the class (or edit the empty one) ──
  private apiUrl = 'https://jsonplaceholder.typicode.com/users';

  constructor(private http: HttpClient) { }

// ── 3. ADD these methods to the class ──

  /** The raw response, straight from the API — no conversion. */
  getUsersRaw(): Observable<ApiUser[]> {
    return this.http.get<ApiUser[]>(this.apiUrl);
  }

  /** The same call, converted into OUR Employee shape. */
  getEmployeesFromApi(): Observable<Employee[]> {
    return this.http.get<ApiUser[]>(this.apiUrl).pipe(
      map(users => users.map(u => this.toEmployee(u)))
    );
  }

  /** Turn one ApiUser into one Employee. All the ugliness lives here. */
  private toEmployee(u: ApiUser): Employee {
    return {
      id: u.id,
      name: u.name.toLowerCase(),
      designation: u.company.name,              // the API has no job title, so use the company
      salary: 20000 + (u.id * 2500),            // invented — the API has no salary
      status: u.id % 2 === 1 ? 'Active' : 'Inactive',
      email: u.email
    };
  }
LineWhat it does
constructor(private http: HttpClient)Dependency injection again — the third time today. Angular supplies the HttpClient.
this.http.get<ApiUser[]>(url)Sends a GET. The <ApiUser[]> tells TypeScript the response shape, which gives you autocomplete on server data.
Observable<Employee[]>The return type. Not the data — a promise of future data. The coffee ticket, not the coffee.
.pipe(map(...))Transforms the data as it flows through. The outer map is an RxJS operator on the stream; the inner users.map is the ordinary array method from Session 1.
private toEmployee(u)All the awkward conversion in one private place. If the API changes, this is the only method you touch.
Yes, the salary is invented — and that's the honest thing to do This API has no salary field, so toEmployee makes one up from the id. In a real project you would either change the API or leave the field out. We fabricate it here so the rest of your existing table, pipes and colour coding keep working unchanged.

  constructor(private fb: FormBuilder,
              private employeeService: EmployeeService) {
    this.empForm = this.fb.group({ /* ...unchanged... */ });

// add these members
  isSaving = false;
  serverReply = '';

  saveToApi(): void {
    if (this.empForm.invalid) {
      this.empForm.markAllAsTouched();
      return;
    }

    const emp: Employee = {
      id: 0,                                          // the server assigns the real id
      name: this.empForm.value.name,
      designation: this.empForm.value.designation,
      salary: this.empForm.value.salary,
      status: 'Active',
      email: this.empForm.value.email

    this.serverReply = '';

    this.employeeService.createOnApi(emp).subscribe({
      next: (saved) => {
        // Use what the SERVER returned, not your local copy
        this.serverReply = JSON.stringify(saved, null, 2);
        this.isSaving = false;
        this.empForm.reset({ name: '', email: '', salary: 0,
                             designation: 'Software Engineer' });
      },
      error: (err) => {
        this.serverReply = 'Save failed: ' + err.message;
        this.isSaving = false;
      }
    });
  }

▶ Troubleshooting — Session 3Theory slides 27, 30, 36
Two habits that solve most of today's problems 1. Keep the Network tab open. It tells you whether a request was even made, what you sent, what came back, and the status code. Half of today's bugs are visible there in two seconds.
2. Put {{ myThing | json }} on the page when data looks wrong. It works on form values, API responses, anything.
Message / symptomCause and fix
NullInjectorError: No provider for HttpClient! Add import { HttpClientModule } from '@angular/common/http'; and put HttpClientModule in imports. Note the package — it's @angular/common/http, not @angular/core.
Can't bind to 'formGroup' since it isn't a known property of 'form' ReactiveFormsModule missing from imports. Same error family as ngModel/FormsModule.
If ngModel is used within a form tag, either the name attribute must be set… A template-driven field is missing its name="...". Both name and ngModel are required.
Cannot find control with name: 'name' The formControlName string doesn't match a key in your FormGroup. Check spelling and capitalisation on both sides.
Type 'Observable<Employee[]>' is not assignable to type 'Employee[]' The classic. You wrote this.employees = service.getEmployees();. An HTTP method returns an Observable, not data — you must .subscribe() and assign inside next.
Nothing happens. No request in the Network tab. No error. Missing .subscribe(). Observables are lazy — without a subscriber, no request is ever sent. This is today's single most common bug.
The spinner never stops You forgot isLoading = false in the error handler. Set it in both branches.
Blank screen, and an error only in the console You have no error handler in subscribe, so the failure was reported to a console your user will never open. Always provide one.
blocked by CORS policy A browser security rule, not an Angular bug — the request never reached your server. Fix it on the server: @CrossOrigin(origins = "http://localhost:4200") on your Spring controller. Nothing you change in Angular will help.
404 Not Found in the Network tab The URL is wrong. Copy it out of the Network tab and paste it into a browser tab — if it fails there too, the URL is the problem, not your code.
Data arrives but the table is empty The response shape doesn't match what you assumed. Add {{ myData | json }} to the page and compare it with your interface. This is exactly why ApiUser is separate from Employee.
Cannot read properties of undefined right after loading The template rendered before the reply arrived. Guard it with *ngIf="data" or use ?. — {{ emp?.name }}.
Two identical requests for the same data Two separate | async subscriptions. Use *ngIf="data$ | async as data" and refer to data thereafter.
Errors appear before the user types anything Your condition is missing && field.touched. Always pair invalid with touched.
Save does nothing on an empty form, with no explanation The form is invalid but no errors show, because nothing is touched. Call this.form.markAllAsTouched() before returning.
Confusing errors on a single input You mixed the two form systems — [(ngModel)] and formControlName on the same element. Pick one per form.
Property 'employees$' has no initializer Strict mode. Write employees$!: Observable<Employee[]>; with the !.
Two components show different data You wrote new EmployeeService() somewhere, creating a second instance. Never use new for a service — inject it.

ngFormThe directive Angular attaches to every <form>; #f="ngForm" gives you the form's state.

FormGroupA collection of form controls — the whole form, or a nested section of it.
FormControlOne field: its value, its validators, and its state.
FormBuilderAn injected service that builds the same structure with much less code: ['', [Validators.required]].
ValidatorsAngular's built-in rules: required, minLength, email, min, max, pattern.
touchedThe user has focused this field and then left it. The flag that makes error messages polite.
dirtyThe value has been changed. Different from touched.
pristineNothing has been changed since the form loaded.
patchValueSet some fields from code. Essential for edit screens (Session 4).
setValueSet every field from code — all of them must be supplied.
markAllAsTouchedReveal every validation error at once, typically on a failed submit.
ServiceA plain class holding reusable data and logic, with no template.
@InjectableMarks a class as available for injection. Angular's @Service.
providedIn: 'root'Registers the service app-wide as a single shared instance.
Dependency injectionDeclaring what you need in a constructor and letting Angular supply it. You never write new.
InjectorAngular's registry that builds and caches service instances.
SingletonOne instance shared by everyone — which is how two components see the same data.
HttpClientAngular's HTTP tool: get, post, put, delete. Belongs in a service.
HttpClientModuleThe module that must be in imports before HttpClient can be injected.
ObservableA value that will arrive later, possibly many times. The coffee ticket, not the coffee.
subscribeRegistering your handlers and starting the work. No subscribe, no request.
next / error / completeThe three subscribe handlers: a value arrived / it failed / the stream ended.
LazyAn Observable does nothing until subscribed to. The cause of most "why isn't it firing" confusion.
RxJSThe library Angular uses for Observables, and the source of operators like map.
pipe(map(...))Transforming data as it flows through an Observable.
async pipeSubscribes in the template and unsubscribes automatically. Cannot leak.
The $ suffixA naming convention: employees$ holds an Observable, employees holds data.
CORSA browser rule blocking requests to a different origin unless the server permits it. Fixed on the server.
OriginProtocol + host + port. localhost:4200 and localhost:8080 are different origins.
