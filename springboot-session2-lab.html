The labs
LAB 1▶ The Student Model Class
Concept — why this class needs getters, setters and a no-arg constructor This class is the shape of our data. Jackson (the JSON library that came with spring-boot-starter-web) uses it in both directions, and each direction needs something different:
  • Going out (Java → JSON), Jackson calls your getters. The JSON key comes from the getter name: getName() becomes "name". No getter means the field silently vanishes from the response.
  • Coming in (JSON → Java), Jackson first calls the no-argument constructor to make an empty object, then calls the setters to fill it. Miss either and you get a 400, or an object where every field is null.
Do this — step by step
  1. Right-click the package com.tcs.training.students.model → New → Class.
  2. Name it Student — capital S, no .java extension.
  3. Select all in the new file, delete, and paste the whole file below.

package com.tcs.training.students.model;

public class Student {

    private int id;
    private String name;
    private String email;
    private String grade;

    // ---- No-argument constructor: REQUIRED by Jackson to read JSON in ----
    public Student() {
    }

    // ---- Convenience constructor, for creating our sample data ----
    public Student(int id, String name, String email, String grade) {
        this.id = id;
        this.name = name;
        this.email = email;
        this.grade = grade;
    }

    // ---- Getters: Jackson uses these to BUILD the JSON going out ----
    public int getId() {
        return id;
    }

    public String getName() {
        return name;
    }

    public String getEmail() {
        return email;
    }

    public String getGrade() {
        return grade;
    }

    // ---- Setters: Jackson uses these to FILL the object coming in ----
    public void setId(int id) {
        this.id = id;
    }

    public void setName(String name) {
        this.name = name;
    }

    public void setEmail(String email) {
        this.email = email;
    }

    public void setGrade(String grade) {
        this.grade = grade;
    }
}
Don't type getters and setters by hand — ever Every IDE writes them for you. Type just the four fields, then: IntelliJ → Alt+Insert → "Getter and Setter" → select all fields. Eclipse → right-click → Source → "Generate Getters and Setters". VS Code → right-click → Source Action → "Generate Getters and Setters". Doing it by hand is slow and typo-prone.
Expected result The file compiles with no red markers. There's nothing to run yet — this class holds data and does nothing on its own.
Why is id an int and not a String? Because ids are numbers we generate and compare. It also gives us free input validation: request /api/students/abc and Spring returns 400 Bad Request automatically, because "abc" can't be converted to an int. You didn't write that check.
LAB 2▶ The StudentService — Our In-Memory Store
Concept — why a separate service class at all? We could keep the list inside the controller, and plenty of tutorials do. We won't, for one concrete reason: in Session 3 we swap this list for a real database. Because the controller will only ever talk to StudentService — never to the list itself — that swap means rewriting this class and leaving the controller completely untouched. That's the layered architecture from Session 1 earning its keep.

Note also that a @Service bean is a singleton — one instance for the whole application — so there is one shared list that every request sees. That's what makes it behave like a tiny database while the app is running.
Do this — step by step

  2. Name it StudentService.
  3. Paste the whole file below.
📄src/main/java/com/tcs/training/students/service/StudentService.javacreate this — paste the WHOLE file
package com.tcs.training.students.service;

import com.tcs.training.students.model.Student;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

// @Service = "Spring, create ONE of these and manage it."
// Because it is a singleton, the list below is shared by every request.
@Service
public class StudentService {

    private final List<Student> students = new ArrayList<>();
    private int nextId = 1;

    // Constructor: seed three students so our GET endpoints have something
    // to return straight away.
    public StudentService() {
        students.add(new Student(nextId++, "Amit Shah",  "amit@tcs.com",  "A"));
        students.add(new Student(nextId++, "Neha Patel", "neha@tcs.com",  "B"));
        students.add(new Student(nextId++, "Ravi Kumar", "ravi@tcs.com",  "A"));
    }

    // ---- READ ALL ----
    public List<Student> findAll() {
        return students;
    }

    // ---- READ ONE: returns null if there is no such id ----
    public Student findById(int id) {
        for (Student s : students) {
            if (s.getId() == id) {
                return s;
            }
        }
        return null;
    }

    // ---- FILTER by grade (case-insensitive) ----
    public List<Student> findByGrade(String grade) {
        List<Student> result = new ArrayList<>();
        for (Student s : students) {
            if (s.getGrade().equalsIgnoreCase(grade)) {
                result.add(s);
            }
        }
        return result;
    }

    // ---- CREATE: we assign the id, never the client ----
    public Student save(Student student) {
        student.setId(nextId++);
        students.add(student);
        return student;
    }

    // ---- UPDATE: returns null if the id doesn't exist ----
    public Student update(int id, Student updated) {
        Student existing = findById(id);
        if (existing == null) {
            return null;
        }
        existing.setName(updated.getName());
        existing.setEmail(updated.getEmail());
        existing.setGrade(updated.getGrade());
        return existing;
    }

    // ---- DELETE: returns true if something was actually removed ----
    public boolean delete(int id) {
        Student existing = findById(id);
        if (existing == null) {
            return false;
        }
        students.remove(existing);
        return true;
    }
}
Expected result Compiles cleanly. Still nothing to run — no endpoint exposes it yet. That's Lab 3.
Read the method signatures — they're a deliberate design findById returns null when nothing is found, and delete returns false. Those return values are how the controller will know to send a 404 instead of a 200. It works, but it's clumsy — every caller must remember to check. In Session 3 we replace it with a custom exception and a single global handler, which is far cleaner.
LAB 3GET▶ The Controller & GET All Students
Concept — three things happening at once
  • @RequestMapping("/api/students") on the class sets the prefix for every method inside. So a bare @GetMapping with no path answers /api/students exactly.
  • The constructor asks for a StudentService. Spring finds the bean it created from your @Service class and passes it in — dependency injection, exactly as in Session 1.
  • The method returns List<Student>, and Jackson turns that into a JSON array. You write no conversion code.

    @GetMapping

LAB 4GET▶ GET One Student — and a Proper 404
Concept — @PathVariable and ResponseEntity @GetMapping("/{id}") declares a slot in the path. Request /api/students/2 and Spring puts 2 into the method's id parameter, converting the text to an int for you.

The interesting part is what happens when the id doesn't exist. Returning null would give the caller 200 OK with an empty body — a lie, because we're saying "success" about a failure. Instead we return ResponseEntity, which lets us choose the status code: 200 with the student, or 404 with nothing.
Do this — step by step
  1. Open StudentController.java.
  2. Select all, delete, and paste the whole updated file below — it keeps Lab 3's method and adds the new one.
  3. Restart the app.
  4. Try both URLs in the expected-output table — including the one that fails.

package com.tcs.training.students.controller;

import com.tcs.training.students.model.Student;
import com.tcs.training.students.service.StudentService;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/students")
public class StudentController {

    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    // GET /api/students
    @GetMapping
    public List<Student> getAllStudents() {
        return service.findAll();
    }

    // ---- NEW ----
    // GET /api/students/2   ->  200 + that student
    // GET /api/students/99  ->  404, empty body
    @GetMapping("/{id}")
    public ResponseEntity<Student> getStudentById(@PathVariable int id) {
        Student student = service.findById(id);

        if (student == null) {
            return ResponseEntity.notFound().build();   // 404 Not Found
        }
        return ResponseEntity.ok(student);              // 200 OK + body
    }
}

That third row is worth pausing on /api/students/abc gives 400 Bad Request, and you wrote no validation for it. Because the parameter is declared int, Spring tried to convert "abc", failed, and correctly reported a client error. Free type-safety at the edge of your API.
Why 404 and not an empty 200? A status code is a promise to the caller. 200 means "here is what you asked for" — so returning 200 with nothing forces every client to write "if the body is empty, it probably didn't exist" guesswork. 404 says it plainly, and the client can branch on the code alone. Getting this right is much of what separates a usable API from an annoying one.

LAB 5GET▶ Filtering With @RequestParam
Concept — why this is a query parameter, not a path variable Apply the test from the theory deck: is this value needed to identify the resource? A grade isn't — /api/students is perfectly meaningful without it. The grade merely narrows the list. So it belongs after the ? as a query parameter: /api/students/search?grade=A. Ids identify (path); filters narrow (query).
Do this
  1. Add the two imports and the one new method below to StudentController.java. (Or paste the complete file from the reference section at the bottom.)
  2. Restart, then try the three URLs.
📄StudentController.java — add these importsadd to the import block
import org.springframework.web.bind.annotation.RequestParam;
📄StudentController.java — add this method inside the classadd this method
    // GET /api/students/search?grade=A
    // 'required = false' + a default means the parameter is optional.
    @GetMapping("/search")
    public List<Student> searchByGrade(
            @RequestParam(defaultValue = "A") String grade) {
        return service.findByGrade(grade);
    }
⚠️ Order matters here — put /search ABOVE /{id} @GetMapping("/{id}") is a wildcard: it would happily match the literal path /search too, and then fail trying to turn "search" into an int. Spring's matching prefers the more specific literal path, so this normally resolves correctly — but declaring /search before /{id} in the file makes the intent obvious to the next reader and avoids surprises. If you get a strange 400 on /api/students/search, this is the cause.

Why is an empty list 200 and not 404? Because the question "which students have grade Z?" has a perfectly valid answer: none. The collection exists; it's just empty right now. That's a success, so 200 with [] is correct. Contrast Lab 4: "give me student 99" has no valid answer at all, because that resource doesn't exist — hence 404. Empty collection → 200. Missing single item → 404.
Stretch goal Add a second filter so you can search by name fragment: /api/students/search?grade=A&name=am. You'll need another @RequestParam(required = false) String name and a toLowerCase().contains(...) check in the service. Real APIs combine filters exactly like this.
LAB 6POST▶ Creating Data With @RequestBody and 201
Concept — your first write operation Everything so far has been read-only, and all input came from the URL. A whole student record is far too much for a URL, so the client sends JSON in the request body instead. @RequestBody Student student tells Spring: take the JSON body, hand it to Jackson, and give me back a filled-in Student object. Jackson uses the no-arg constructor and the setters you wrote in Lab 1 — which is exactly why they were needed.

And because this creates something, the correct status code is 201 Created, not 200.
⚠️ From here on, a browser will not work A browser address bar can only send GET. To send a POST with a body you need Postman, curl, or the Swagger UI from the bonus lab.

📄StudentController.java — add this method inside the classadd this method
    // POST /api/students   + a JSON body
    // @RequestBody: Jackson converts the incoming JSON into a Student object.
    @PostMapping
    public ResponseEntity<Student> createStudent(@RequestBody Student student) {
        Student saved = service.save(student);

        // 201 Created is the correct code for a successful creation,
        // and we return the saved object so the client learns its new id.
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

Common issues

SymptomCauseFix
415 Unsupported Media Type The Content-Type: application/json header is missing. By far the most common issue in this lab. In Postman: Body → raw → pick JSON (not Text) from the dropdown. With curl: include -H "Content-Type: application/json".
400 Bad Request Malformed JSON — a trailing comma, single quotes, or a missing brace. Keys and strings in double quotes; no comma after the last pair.
405 Method Not Allowed You sent GET (or forgot to change the verb) to the POST endpoint. Set the verb dropdown to POST.
201, but every field is null Your Student class is missing setters, or the JSON keys don't match the field names. Check for setters, and that the keys are exactly name, email, grade.
New student disappears after a restart Working as designed — the list lives in memory. Nothing to fix. Session 3 adds a real database.
Try it — feel the "not idempotent" problem Click Send on the same POST three times, then GET /api/students. You now have three identical Priyas with different ids. That's POST not being idempotent, exactly as the theory said — and it's why a mobile app can't blindly retry a failed POST after a dropped connection.
LAB 7PUTDELETE▶ Update & Delete — Completing CRUD
Concept — the last two operations
  • PUT /api/students/5 needs both kinds of input: a @PathVariable to say which student, and a @RequestBody to say what the new values are. Returns 200 with the updated object, or 404.
  • DELETE /api/students/5 needs only the id and sends no body back — so the right code is 204 No Content: "it worked, and there's nothing to show you." Note the return type ResponseEntity<Void>, since there's no body type.

📄StudentController.java — add both methods inside the classadd these methods
    // PUT /api/students/2   + a JSON body
    // Needs BOTH: the id (which student) and the body (the new values).
    @PutMapping("/{id}")
    public ResponseEntity<Student> updateStudent(@PathVariable int id,
                                                 @RequestBody Student student) {
        Student updated = service.update(id, student);

        if (updated == null) {
            return ResponseEntity.notFound().build();   // 404 — no such id
        }
        return ResponseEntity.ok(updated);              // 200 + updated object
    }

    // DELETE /api/students/3   (no body, in or out)
    // ResponseEntity<Void> because there is no body type to declare.
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteStudent(@PathVariable int id) {
        boolean removed = service.delete(id);

        if (!removed) {
            return ResponseEntity.notFound().build();   // 404 — no such id
        }
        return ResponseEntity.noContent().build();      // 204 No Content
    }

package com.tcs.training.students.service;

import com.tcs.training.students.model.Student;
import org.springframework.stereotype.Service;

import java.util.ArrayList;
import java.util.List;

@Service
public class StudentService {

    private final List<Student> students = new ArrayList<>();
    private int nextId = 1;

    public StudentService() {
        students.add(new Student(nextId++, "Amit Shah",  "amit@tcs.com", "A"));
        students.add(new Student(nextId++, "Neha Patel", "neha@tcs.com", "B"));
        students.add(new Student(nextId++, "Ravi Kumar", "ravi@tcs.com", "A"));
    }

    public List<Student> findAll() {
        return students;
    }

    public Student findById(int id) {
        for (Student s : students) {
            if (s.getId() == id) {
                return s;
            }
        }
        return null;
    }

    public List<Student> findByGrade(String grade) {
        List<Student> result = new ArrayList<>();
        for (Student s : students) {
            if (s.getGrade().equalsIgnoreCase(grade)) {
                result.add(s);
            }
        }
        return result;
    }

    public Student save(Student student) {
        student.setId(nextId++);
        students.add(student);
        return student;
    }

    public Student update(int id, Student updated) {
        Student existing = findById(id);
        if (existing == null) {
            return null;
        }
        existing.setName(updated.getName());
        existing.setEmail(updated.getEmail());
        existing.setGrade(updated.getGrade());
        return existing;
    }

    public boolean delete(int id) {
        Student existing = findById(id);
        if (existing == null) {
            return false;
        }
        students.remove(existing);
        return true;
    }
}

package com.tcs.training.students.controller;

import com.tcs.training.students.model.Student;
import com.tcs.training.students.service.StudentService;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/students")
public class StudentController {

    private final StudentService service;

    public StudentController(StudentService service) {
        this.service = service;
    }

    // GET /api/students
    @GetMapping
    public List<Student> getAllStudents() {
        return service.findAll();
    }

    // GET /api/students/search?grade=A
    // Declared BEFORE /{id} so the literal path is unambiguous to readers.
    @GetMapping("/search")
    public List<Student> searchByGrade(
            @RequestParam(defaultValue = "A") String grade) {
        return service.findByGrade(grade);
    }

    // GET /api/students/2
    @GetMapping("/{id}")
    public ResponseEntity<Student> getStudentById(@PathVariable int id) {
        Student student = service.findById(id);
        if (student == null) {
            return ResponseEntity.notFound().build();
        }
        return ResponseEntity.ok(student);
    }

    // POST /api/students
    @PostMapping
    public ResponseEntity<Student> createStudent(@RequestBody Student student) {
        Student saved = service.save(student);
        return ResponseEntity.status(HttpStatus.CREATED).body(saved);
    }

    // PUT /api/students/2
    @PutMapping("/{id}")
    public ResponseEntity<Student> updateStudent(@PathVariable int id,
                                                 @RequestBody Student student) {
        Student updated = service.update(id, student);
        if (updated == null) {
            return ResponseEntity.notFound().build();
        }
        return ResponseEntity.ok(updated);
    }

    // DELETE /api/students/3
    @DeleteMapping("/{id}")
    public ResponseEntity<Void> deleteStudent(@PathVariable int id) {
        boolean removed = service.delete(id);
        if (!removed) {
            return ResponseEntity.notFound().build();
        }
        return ResponseEntity.noContent().build();
    }
}
▶ 🔧 Troubleshooting Guide
SymptomCauseFix
415 Unsupported Media Type on POST/PUT No Content-Type: application/json header. The most common Session 2 error. Postman: Body → raw → select JSON (not Text). curl: add -H "Content-Type: application/json".
400 Bad Request on POST/PUT Malformed JSON, or a value that can't convert (e.g. text where an int is expected). Double quotes on all keys and strings; no trailing comma; check field names match exactly.
404 Whitelabel on every endpoint The controller is outside the scanned packages, or you didn't restart. Restart. Then confirm the file's first line is package com.tcs.training.students.controller; — with .students. present.
404 on one endpoint only Path mismatch. Remember the real path is class prefix + method path. Class has /api/students, so the method should be @GetMapping("/{id}") — not the full path again.
405 Method Not Allowed Right path, wrong verb. Check the Postman verb dropdown matches the annotation you wrote.
Response is {} or fields are missing The Student class has no getters — Jackson can't read the values out. Generate getters (IntelliJ: Alt+Insert).
201 returned, but all fields null No setters, or no no-arg constructor — Jackson couldn't populate the object. Add both. Confirm the JSON keys match the field names exactly (case-sensitive).
Ambiguous mapping at startup Two methods claim the same verb + path. Each verb+path pair must be unique. /search and /{id} are distinct — that's fine.
400 on /api/students/search @GetMapping("/{id}") matched first and tried to parse "search" as an int. Declare the /search method above the /{id} method in the file.
All data resets on restart The list lives in memory. Expected behaviour. Nothing to fix — Session 3 introduces a real database.
Port 8080 was already in use Session 1's app is probably still running. Stop it, or set server.port=8081 in application.properties.
