Part 1 — The language
TASK 1▶ TypeScript DrillsTheory slides 17–30
Goal Practise each TypeScript idea the moment it is explained, while it is still fresh. Twelve short drills, one per concept. Each drill gives you a "Try it yourself" prompt first — attempt it before opening the solution. Struggling for thirty seconds is what makes a thing stick; reading the answer straight away does not.
Set up your scratch pad — pick one option
  1. Easiest, and what we recommend: open https://www.typescriptlang.org/play in a browser tab. It compiles as you type, shows errors as red squiggles, and the Logs panel on the right shows your console.log output. Nothing to install.
  2. Local alternative: make a folder, add a file drills.ts, run npm install -g typescript once, then compile and run with tsc drills.ts && node drills.js.

Drill A — an inferred variable (slide 17)

Try it yourself Declare a variable holding the text "Hello World" without writing a type. Print it. Then try to assign the number 100 to it. What does the compiler say — and why, given that you never mentioned a type at all?
▶ Show solution A 
let greeting = "Hello World";   // TypeScript INFERS the type: string
console.log(greeting);

greeting = "Goodbye";           // OK — still a string
// greeting = 100;              // remove the // to see the error
What you should see Hello World in the Logs. Now hover your mouse over greeting — a tooltip says let greeting: string. You never typed the word "string", but TypeScript worked it out from the value you assigned. That is inference: type safety for free. Uncomment the last line and a red squiggle appears with Type 'number' is not assignable to type 'string'.

Drill B — explicit types (slides 17–18)

Try it yourself Declare three variables with explicit types: a string employee name, a number age, and a boolean flag. Print all three on one line.
▶ Show solution B 
let empName: string = "Anoop";
let empAge: number = 40;
let isActive: boolean = true;

console.log(empName + " | " + empAge + " | " + isActive);
// Anoop | 40 | true

// Now break each one deliberately and READ the error text:
// empAge = "forty";
// isActive = "yes";
// empName = 42;
What you should see Anoop | 40 | true. Each commented line, when uncommented, gives its own clear message naming both types. Getting familiar with the wording of these errors now means you will recognise them instantly later.
Small gotcha in the Playground Avoid naming a variable just name. The browser already has a global called name and you will get a confusing conflict. empName is safe.

Drill C — let vs const (slide 17)

Try it yourself Declare one variable with let and one with const. Try to reassign both. Which one complains, and what exactly does it say?
▶ Show solution C 
let counter = 0;
counter = 1;              // ✔ fine — let allows reassignment
counter = 2;              // ✔ fine
console.log(counter);     // 2

const companyName = "TCS";
// companyName = "Infosys";   // ✖ Cannot assign to 'companyName' because it is a constant
console.log(companyName);     // TCS

// IMPORTANT subtlety — const locks the VARIABLE, not the object's contents:
const emp = { name: "Anoop", salary: 25000 };
emp.salary = 30000;       // ✔ allowed! we changed a property, not the variable
// emp = { name: "Ajay", salary: 40000 };   // ✖ NOT allowed — reassigning the variable
console.log(emp.salary);  // 30000
What you should see 2, then TCS, then 30000. The important lesson is the last block: const means "this name will always point at this same object" — not "this object can never change". That surprises nearly everyone once.
Habit worth forming today Reach for const first, every time. Switch to let only when you actually need to reassign. Real Angular code is mostly const, and a reader can then trust that a const never changes underneath them.

Drill D — the any trap (slide 19)

Try it yourself Create a variable typed any holding an object with a name property. Then deliberately misspell the property when reading it, and call a method that does not exist. How many errors does TypeScript report? Now change any to a proper type and count again.
▶ Show solution D 
// ---------- Version 1: any ----------
let loose: any = { name: "Anoop" };

console.log(loose.nmae);        // no error reported — but prints: undefined
// loose.doSomething();         // no error reported — CRASHES at runtime

// ---------- Version 2: a real type ----------
let tight: { name: string } = { name: "Anoop" };

// console.log(tight.nmae);     // ✖ Property 'nmae' does not exist on type '{ name: string; }'
// tight.doSomething();         // ✖ Property 'doSomething' does not exist
console.log(tight.name);       // Anoop
What you should see Version 1 reports zero errors and prints undefined — the typo sailed straight through. Version 2 reports two errors, both in your editor, before the code ever ran. That difference is the entire argument for TypeScript, in one drill.
The rule for this series You may use any when you are stuck and want to keep moving — but treat it as a note to come back to, never as a fix. Every any is a spot where TypeScript has stopped protecting you.

Drill E — your first interface (slide 20)

Try it yourself Define an interface called Employee with four properties: id (number), name (string), designation (string) and salary (number). Create one valid employee object. Then create a second one that is missing a property, and a third with a wrong type, and read both errors.
▶ Show solution E 
interface Employee {
  id: number;
  name: string;
  designation: string;
  salary: number;
}

// ✔ Valid — all four properties, all correct types
const e1: Employee = {
  id: 1001,
  name: "Anoop",
  designation: "Software Engineer",
  salary: 25000
};
console.log(e1.name + " — " + e1.designation);

// ✖ Missing properties
// const e2: Employee = { id: 1002, name: "Ajay" };
//    Property 'designation' is missing in type ... but required in type 'Employee'

// ✖ Wrong type
// const e3: Employee = { id: "1003", name: "Rekha", designation: "Tester", salary: 22000 };
//    Type 'string' is not assignable to type 'number'

// Now try the magic bit: on a new line, type   e1.   and then STOP.
// Don't press anything else — just look at the list your editor pops up.
What you should see Anoop — Software Engineer. More importantly, when you type e1. and pause, your editor offers exactly four suggestions: id, name, designation, salary. That autocomplete list is the interface paying you back — and it is why experienced developers write interfaces before they write logic.
Why this drill matters more than the others From Session 2 onwards, almost every piece of data in your app will be described by an interface exactly like this one. When JSON arrives from your Spring Boot API in Session 3, you will say "this response is an Employee[]" and get this same autocomplete and typo protection on live server data.

Drill F — optional properties, ?. and ?? (slide 21)

Try it yourself Add an optional email property to your Employee interface. Create one employee with an email and one without. Then try to call .toUpperCase() on the email of the one that hasn't got one — and fix the resulting error three different ways.
▶ Show solution F 
interface Employee {
  id: number;
  name: string;
  email?: string;          // ← the ? makes it optional
}

const withEmail: Employee    = { id: 1, name: "Ajay", email: "ajay@example.com" };
const withoutEmail: Employee = { id: 2, name: "Anoop" };   // ✔ valid — no email

// ✖ This is an error: 'withoutEmail.email' is possibly 'undefined'
// console.log(withoutEmail.email.toUpperCase());

// Fix 1 — check that it exists first
if (withoutEmail.email) {
  console.log(withoutEmail.email.toUpperCase());
} else {
  console.log("no email on file");
}

// Fix 2 — optional chaining: "only continue if the left side exists"
console.log(withoutEmail.email?.toUpperCase());    // undefined
console.log(withEmail.email?.toUpperCase());       // AJAY@EXAMPLE.COM

// Fix 3 — nullish coalescing: supply a fallback value
console.log(withoutEmail.email ?? "no email on file");   // no email on file
console.log(withEmail.email ?? "no email on file");      // ajay@example.com
What you should see no email on file, then undefined, then AJAY@EXAMPLE.COM, then no email on file, then ajay@example.com. Note that Fix 2 gives you undefined rather than a crash — that is the whole point of ?.
Learn these two symbols properly — you will use them constantly ?. = "only carry on if the thing on the left actually exists".
?? = "use the right-hand value if the left is null or undefined".
In Session 3 your template will render before the server has replied, so your data will briefly be undefined. ?. is what stops that half-second from throwing an error.

Drill G — union types (slide 22)

Try it yourself Declare a variable that may hold either a number or a string, and assign each in turn. Then create a Status type that allows only the three exact words "Active", "Inactive" and "OnLeave", and try assigning "active" in lower case.
▶ Show solution G 
// A plain union — "either of these types"
let empId: number | string;

empId = 1001;            // ✔
console.log(empId);
empId = "EMP-1001";      // ✔
console.log(empId);
// empId = true;         // ✖ 'boolean' is not assignable to 'number | string'

// A LITERAL union — only these three exact strings are allowed.
// This is TypeScript's answer to a Java enum.
type Status = "Active" | "Inactive" | "OnLeave";

let s1: Status = "Active";      // ✔
console.log(s1);
// let s2: Status = "active";   // ✖ wrong case — caught immediately
// let s3: Status = "Retired";  // ✖ not one of the three

// Using it inside an interface — this is the real-world shape
interface Employee {
  id: number;
  name: string;
  status: Status;
}

const e: Employee = { id: 1001, name: "Anoop", status: "Active" };
console.log(e.name + " is " + e.status);
What you should see 1001, EMP-1001, Active, then Anoop is Active. Now delete the word "Active" from the last object and retype the opening quote — your editor offers you the three legal values as a dropdown. You literally cannot get it wrong.
Why not just use string? Because "Actve" would compile perfectly happily, and in Session 2 you will colour rows green or red based on this exact field. A one-letter typo would silently show the wrong colour, with no error anywhere. As a literal union, that typo is a red squiggle before you even save.

Drill H — typed arrays and the six methods that matter (slide 23)

Try it yourself Build an array of four Employee objects. Then, without writing a single loop, answer these four questions in code: who earns more than 30000? who has id 1002? what are all the names? how many are there?
▶ Show solution H 
interface Employee {
  id: number;
  name: string;
  designation: string;
  salary: number;
}

let employees: Employee[] = [
  { id: 1001, name: "Anoop",  designation: "Software Engineer", salary: 25000 },
  { id: 1002, name: "Ajay",   designation: "Team Lead",         salary: 45000 },
  { id: 1003, name: "Rekha",  designation: "Tester",            salary: 22000 },
  { id: 1004, name: "Suresh", designation: "Architect",         salary: 65000 }
];

// How many?
console.log(employees.length);                       // 4

// Who earns more than 30000?  → filter returns a NEW array
const wellPaid = employees.filter(e => e.salary > 30000);
console.log(wellPaid.length);                        // 2
console.log(wellPaid.map(e => e.name));              // [ 'Ajay', 'Suresh' ]

// Who has id 1002?  → find returns ONE item, or undefined
const found = employees.find(e => e.id === 1002);
console.log(found?.name);                            // Ajay

// All the names → map transforms every item
console.log(employees.map(e => e.name));             // [ 'Anoop', 'Ajay', 'Rekha', 'Suresh' ]

// Where is id 1003?  → findIndex gives a position, or -1
console.log(employees.findIndex(e => e.id === 1003));   // 2

// Insert one
employees.push({ id: 1005, name: "Priya", designation: "Analyst", salary: 28000 });
console.log(employees.length);                       // 5

// Delete the one at position 2 (Rekha) — remove 1 item starting at index 2
employees.splice(2, 1);
console.log(employees.map(e => e.name));             // [ 'Anoop', 'Ajay', 'Suresh', 'Priya' ]
What you should see In order: 4, 2, [ 'Ajay', 'Suresh' ], Ajay, the four names, 2, 5, then the list with Rekha gone.
This drill is secretly Session 4 In Session 4 you build a complete CRUD screen, and it is literally these six methods: push to insert, filter to search, findIndex + splice to delete, find to load a row for editing. If you are comfortable here, Session 4 will feel like revision. If not, redo this drill tonight — it is the highest-value fifteen minutes in the whole series.
Note the ?. coming back found?.name uses optional chaining, because find() returns Employee | undefined — there may not be a match. TypeScript forces you to acknowledge that, which is exactly the null check you would otherwise have forgotten.

Drill I — tuples (slide 24)

Try it yourself Declare a tuple holding exactly a number then a string. Do arithmetic on the first item and call a string method on the second. Then try putting them in the wrong order, and try adding a third item.
▶ Show solution I 
// A tuple: exactly two items — a number first, then a string
let emp: [number, string] = [1001, "Anoop"];

console.log(emp[0] + 1);              // 1002    — TypeScript knows [0] is a number
console.log(emp[1].toUpperCase());    // ANOOP   — and that [1] is a string

// ✖ Wrong order — the position of each type is fixed
// let bad: [number, string] = ["Anoop", 1001];

// ✖ Wrong length — a tuple has a fixed number of slots
// let tooMany: [number, string] = [1001, "Anoop", true];

// Compare with the interface version of the same data:
interface Emp { id: number; name: string; }
const better: Emp = { id: 1001, name: "Anoop" };
console.log(better.id + 1);           // 1002 — but now it's obvious WHAT id is
What you should see 1002, then ANOOP, then 1002 again. Notice that emp[0] tells a reader nothing, while better.id explains itself.
Honest guidance Tuples turn up in exam questions far more often than in real Angular code, because an interface is nearly always clearer. Learn to recognise them; reach for interfaces when you write your own code.

Drill J — the three loops, and the classic trap (slide 25)

Try it yourself Print the same array of three names using all three loop styles. Then, in the for...in version, print i + 1. Look very carefully at what it prints — it is not what you expect.
▶ Show solution J 
let names: string[] = ["Anoop", "Ajay", "Rekha"];

// 1 — classic for: you control the index
console.log("--- classic for ---");
for (let i = 0; i < names.length; i++) {
  console.log(i + " → " + names[i]);
}

// 2 — for...OF: gives you each VALUE  (the one you usually want)
console.log("--- for...of ---");
for (const n of names) {
  console.log(n);
}

// 3 — for...IN: gives you each INDEX, as a STRING
console.log("--- for...in ---");
for (const i in names) {
  console.log(i + 1);             // ← LOOK CLOSELY at this output
}
What you should see — and the trap The first loop prints 0 → Anoop, 1 → Ajay, 2 → Rekha. The second prints the three names.
The third prints 01, 11, 21 — not 1, 2, 3! Because for...in hands you the string "0", and "0" + 1 in JavaScript means join these together, giving "01". This is a genuinely famous bug and now you have seen it happen.
Memorise this one line for...of → the object / the value. for...in → the index / the key. For arrays you almost always want of.

Drill K — functions and arrow functions (slides 26–27)

Try it yourself Write a normal function add(a, b) that returns a number. Write a void function that only prints. Write a function with a default parameter. Then rewrite add as an arrow function, in the shortest form you can manage.
▶ Show solution K 
// 1 — a normal typed function
function add(a: number, b: number): number {
  return a + b;
}
console.log(add(5, 3));            // 8
// console.log(add("5", 3));       // ✖ 'string' is not assignable to 'number'
// console.log(add(5));            // ✖ Expected 2 arguments, but got 1

// 2 — returns nothing: void
function logEmployee(name: string, salary: number): void {
  console.log(name + " earns " + salary);
}
logEmployee("Anoop", 25000);       // Anoop earns 25000

// 3 — a default parameter
function raise(salary: number, percent: number = 10): number {
  return salary + (salary * percent / 100);
}
console.log(raise(20000));         // 22000  — used the default 10
console.log(raise(20000, 25));     // 25000

// 4 — the same 'add', as an arrow function, three ways
const addA = function (a: number, b: number): number { return a + b; };
const addB = (a: number, b: number): number => { return a + b; };
const addC = (a: number, b: number): number => a + b;    // shortest: implicit return
console.log(addA(1, 2), addB(3, 4), addC(5, 6));         // 3 7 11

// 5 — one parameter needs no brackets at all
const double = (n: number) => n * 2;
console.log(double(21));           // 42
What you should see 8, Anoop earns 25000, 22000, 25000, 3 7 11, 42.
Read the arrow out loud (a, b) => a + b reads as "given a and b, produce a + b". When there are no curly braces, the value is returned automatically — you must not write return. If you have used Java streams, this is exactly a lambda; Java writes -> where TypeScript writes =>.

Drill L — a class, and the constructor shorthand (slides 28–29)

Try it yourself Write an Employee class with three fields, a constructor, and two methods: one returning a formatted string, one applying a percentage pay rise. Create an instance and use both. Then rewrite the constructor using the shorthand so the three assignment lines disappear.
▶ Show solution L

The long form

class Employee {
  id: number;
  name: string;
  salary: number;

  constructor(id: number, name: string, salary: number) {
    this.id = id;
    this.name = name;
    this.salary = salary;
  }

  getDetails(): string {
    return this.id + " — " + this.name + " (" + this.salary + ")";
  }

  applyRaise(percent: number): void {
    this.salary = this.salary + (this.salary * percent / 100);
  }
}

const e = new Employee(1001, "Anoop", 25000);
console.log(e.getDetails());     // 1001 — Anoop (25000)
e.applyRaise(10);
console.log(e.getDetails());     // 1001 — Anoop (27500)

The same class using the constructor shorthand

class Employee2 {
  // An access modifier on a constructor parameter declares AND assigns
  // the field automatically. Those three 'this.x = x' lines are gone.
  constructor(
    public id: number,
    public name: string,
    private salary: number
  ) { }

  getDetails(): string {
    return this.id + " — " + this.name + " (" + this.salary + ")";
  }
}

const e2 = new Employee2(1002, "Ajay", 45000);
console.log(e2.getDetails());    // 1002 — Ajay (45000)
console.log(e2.name);            // Ajay  — public, so readable from outside
// console.log(e2.salary);       // ✖ 'salary' is private and only accessible inside the class
What you should see 1001 — Anoop (25000), 1001 — Anoop (27500), then 1002 — Ajay (45000) and Ajay. Uncomment the last line to confirm that private genuinely blocks outside access.
Remember this drill in Session 3 — seriously In Session 3 you will write constructor(private http: HttpClient) { } and reasonably wonder where the http field came from, since nothing declared it. This is where. The word private on that parameter declared and assigned the field for you. Every Angular component and service uses this exact pattern, so it is worth fixing in your memory now.

src/index.htmlThe one and only page of your single-page application. Its body contains just <app-root></app-root> — your entire app gets injected into that empty tag.
src/main.tsThe entry point — the first of your code to run. It calls bootstrapModule(AppModule), meaning "start Angular here". You will almost never edit it.
src/app/app.module.tsThe registry. declarations lists your own components; imports lists feature modules from elsewhere; providers lists services; bootstrap names the starting component. Angular refuses to use anything not listed here.
src/app/app.component.tsThe root component class — your logic and data. Its selector is 'app-root', which is exactly the tag you found in index.html. That is the link you were looking for.
src/app/app.component.htmlThe root component's template — the markup the user sees. All of that generated welcome-page content lives here, which is why deleting it in Task 4 blanks the page.
src/app/app.component.cssStyles for this component only. Empty right now. Anything you put here cannot leak out and affect other components — Angular scopes it automatically.
src/styles.cssGlobal styles, applied to the whole application. This is where a CSS framework like Bootstrap would be imported.
package.jsonYour pom.xml. Lists every dependency plus named scripts. npm start is wired to run ng serve.
angular.jsonCLI configuration — build options, output folders, which files to include. Advanced; leave it alone for now.
node_modules/Every downloaded library. Typically 200–400 MB and tens of thousands of files. Never commit it — it is in .gitignore already, and npm install recreates it from package.json.

Now trace the boot chain yourself

This is the single most useful thing to understand about an Angular project, and it is only four steps. Follow them in your own files, in this order:

Follow the chain
  1. Open src/index.html → find <app-root></app-root>.
  2. Open src/main.ts → find the word AppModule.
  3. Open src/app/app.module.ts → find bootstrap: [AppComponent].
  4. Open src/app/app.component.ts → find selector: 'app-root'. That matches step 1 — the circle closes.
Prove it — a 20-second experiment In src/app/app.component.ts, change selector: 'app-root' to selector: 'app-rooot' (three o's) and save. Look at your browser: the page goes blank, because index.html is still asking for <app-root> and nothing answers to that name any more. Press F12 and read the console message. Then change it back and the page returns. You have just proved the chain is real, and seen what a blank page actually means.

📄 src/app/models/employee.ts Replace the whole file 
export interface Employee {
  id: number;
  name: string;
  designation: string;
  salary: number;
  status: 'Active' | 'Inactive';     // a literal union — only these two words
  email?: string;                    // optional — may be missing
}
LineWhy it is written that way
export interfaceexport means other files may import this. Without it, the interface is private to this file and you will get "has no exported member".
status: 'Active' | 'Inactive'A literal union. Only those two exact strings compile — 'active' in lower case is an error. In Session 2 you colour rows from this field, and this is what stops a typo silently breaking the colours.
email?: stringThe ? makes it optional. TypeScript will now force you to handle the case where it is missing.

Step 2 — use it in your component

📄 src/app/app.component.ts Replace the whole file 
import { Component } from '@angular/core';
import { Employee } from './models/employee';

@Component({
  selector: 'app-root',
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css']
})
export class AppComponent {
  title = 'My Employee Directory';

  // A typed array — TypeScript checks every single object below
  employees: Employee[] = [
    { id: 1001, name: 'Anoop',  designation: 'Software Engineer', salary: 25000, status: 'Active' },
    { id: 1002, name: 'Ajay',   designation: 'Team Lead',         salary: 45000, status: 'Inactive' },
    { id: 1003, name: 'Rekha',  designation: 'Tester',            salary: 22000, status: 'Active' },
    { id: 1004, name: 'Suresh', designation: 'Architect',         salary: 65000, status: 'Inactive' }
  ];

  // A method the template can call
  getTotalSalary(): number {
    let total = 0;
    for (const e of this.employees) {
      total = total + e.salary;
    }
    return total;
  }

  getActiveCount(): number {
    return this.employees.filter(e => e.status === 'Active').length;
  }
}
Keep whatever @Component block the CLI gave you If your generated file said styleUrl (singular) or included standalone: true, keep those lines exactly as they were and change only the class body below them. Copying the block above verbatim onto a newer CLI's file is a common cause of confusing errors.

selected: Employee = null;   // ✖ Type 'null' is not assignable to type 'Employee'

▶ Troubleshooting — every error you're likely to hit todayTheory slide 40

Find your error message in the left column. None of these mean you are doing badly — every one is normal on day one, and every one has a one-line fix.

Message / symptomCause and fix
'ng' is not recognized as an internal or external command
ng: command not found		 Close the terminal and open a brand-new one — a terminal only reads the PATH when it starts, so one that was already open cannot see a tool installed afterwards. This fixes it most of the time. If not, re-run npm install -g @angular/cli and read the output for ERR! lines.
cannot be loaded because running scripts is disabled on this system Windows PowerShell blocking scripts. Run: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned and answer Y. Or just use Command Prompt / Git Bash instead.
Port 4200 is already in use ng serve is already running, probably in another terminal tab. Use the browser tab you already have, or start a second copy elsewhere: ng serve --port 4300.
The serve command requires to be run in an Angular project, but a project definition could not be found You are in the wrong folder — most likely the parent of your project. Run cd hello-world first. The rule: you must be in the folder that contains angular.json.
Cannot find module '@angular/core' node_modules/ is missing or was only partly downloaded. Run npm install inside the project folder. This is also the fix after cloning someone else's project.
has no exported member 'Employee' You forgot the word export in front of interface Employee, or the import path is wrong. Note the path is relative: from app.component.ts it is './models/employee' with no .ts on the end.
Type '"active"' is not assignable to type '"Active" | "Inactive"' Working as designed — your literal union caught a case mismatch. Use the exact capitalisation, or let your editor's autocomplete insert it for you.
Property 'salary' is missing in type ... but required in type 'Employee' Also working as designed — one of your objects is missing a property the interface requires. The error names both the property and the line.
A blank white page, and no error visible anywhere Press F12 and open the browser's Console tab. The real error is always there — Angular does not print it onto the page. Nine times out of ten it is a mismatched selector or a typo in templateUrl.
The page never updates when I save Either ng serve has stopped (check its terminal for a crash or a stray Ctrl+C), or you edited a file outside the project folder. The terminal prints a fresh build line on every successful save — if it's silent, the watcher isn't seeing your file.
{{ myField }} shows nothing at all Angular renders a missing field as an empty string rather than erroring. Almost always a spelling mismatch between the template and the class — check the capitalisation of both very carefully.
Tutorials online use $scope and nothing works You are reading AngularJS 1.x documentation, which is a different framework. Close the tab and search again including a version number, e.g. "Angular 17 ngFor".
npm ERR! ETIMEDOUT / ECONNREFUSED / proxy errors Corporate network. Configure npm's proxy: npm config set proxy http://your-proxy:port and npm config set https-proxy http://your-proxy:port, then retry.
Everything is bizarrely slow, or files randomly lock Your project is inside a OneDrive / Google Drive / Dropbox synced folder. Move it somewhere local — those tools cannot cope with node_modules.
▶ Glossary — every term used todayTheory slide 5
TermMeaning in one sentence
AngularGoogle's TypeScript front-end framework, version 2 and above, for building single-page applications.
AngularJSThe original version 1.x — a different framework. If a tutorial mentions $scope, it is this one.
SPASingle-Page Application: one HTML page is loaded once, then JavaScript swaps sections in and out.
FrameworkA toolkit that provides your app's structure and calls your code. Angular and Spring Boot are both frameworks.
TypeScriptJavaScript plus static types. Types are checked while you write and removed when compiled.
Transpile / compileConverting your .ts files into the .js files a browser can run.
Type inferenceTypeScript working out a type from the value you assigned, so you don't have to write it.
InterfaceA description of the shape an object must have. Exists only at compile time.
Union typeA | B — "either of these". With string literals it acts like an enum.
Optional propertyA property marked with ?, meaning it is allowed to be absent.
Optional chainingThe ?. operator — "only continue if the thing on the left exists".
Nullish coalescingThe ?? operator — "use the right-hand value if the left is null or undefined".
TupleA fixed-length array where each position has its own type.
Arrow function(a) => a * 2 — a compact function. TypeScript's version of a Java lambda.
Node.jsA runtime that executes JavaScript on your machine rather than in a browser. The "JVM" of this world.
npmNode Package Manager — downloads libraries. The "Maven" of this world.
package.jsonThe dependency list and script definitions. The "pom.xml" of this world.
node_modules/The folder holding every downloaded library. Huge, and never committed to git.
Angular CLIThe ng command-line tool — creates projects and files, serves, builds and tests.
ComponentOne piece of screen: a TypeScript class, an HTML template, and a CSS file.
TemplateThe HTML belonging to a component.
DecoratorAn @Something({...}) marker that attaches metadata to a class. Angular's @Component is one; Spring's @RestController is the same idea.
SelectorThe custom HTML tag name that renders a component, e.g. <app-root>.
NgModuleThe registry listing everything your app is made of — declarations, imports, providers, bootstrap.
Bootstrap (verb)Starting the application. Not to be confused with Bootstrap the CSS framework.
InterpolationThe {{ }} syntax that puts a class value into the template. Session 2's first topic.
Live reloadThe dev server watching your files, rebuilding on save, and refreshing the browser for you.
localhost:4200The dev server's address on your own machine. Nobody else can reach it.
dist/The folder ng build produces, holding the deployable files.
