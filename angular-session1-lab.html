TASK 1▶ TypeScript DrillsTheory slides 12–19
Goal Practise every TypeScript concept the moment it's explained, while it's fresh. Seven short drills, one per concept. Each has a "Try it yourself" prompt first — attempt it before opening the solution. Struggling for thirty seconds is what makes it stick.
Set up your scratch pad — pick one
  1. Easiest (recommended): open https://www.typescriptlang.org/play in a browser tab. It compiles as you type, shows errors with red squiggles, and the Logs panel shows your console.log output. Nothing to install.
  2. Local alternative: create a folder, add a file drills.ts, then run npm install -g typescript once and use tsc drills.ts && node drills.js to compile and run.

Drill A — an inferred-type variable (slide 12)

Try it yourself Declare a variable holding the text "Hello World" without writing a type. Then try to assign the number 100 to it. What does the compiler say — and why, if you never mentioned a type?
▶ Show solution A 
let str = "Hello World";     // TypeScript INFERS the type: string
console.log(str);

str = "Goodbye";             // OK — still a string
// str = 100;                // ERROR: Type 'number' is not assignable to type 'string'
What you should see Hover over str in the Playground — a tooltip says let str: string. You never typed "string", but TypeScript worked it out from the initial value. Inference means you get type safety for free. Uncomment the last line to see the red squiggle appear.

Drill B — an explicitly-typed variable (slide 12)

Try it yourself Declare three variables with explicit types: a string name, a number age and a boolean flag. Print all three in one console.log.
▶ Show solution B 
let empName: string = "Anoop";
let empAge: number = 40;
let isActive: boolean = true;

console.log(empName + " | " + empAge + " | " + isActive);
// Anoop | 40 | true

// Bonus — try each of these and read the error text:
// empAge = "forty";
// isActive = "yes";
Note Avoid naming a variable just name in the Playground — the browser already has a global name and you'll get a confusing conflict. empName is safer.

Drill C — an interface + an object (slide 13)

Try it yourself Define an interface Person with name: string, city: string and age: number. Create an object that satisfies it. Then deliberately delete one property and read the error.
▶ Show solution C 
interface Person {
  name: string;
  city: string;
  age: number;
}

let myData: Person = {
  name: "Anoop",
  city: "Trivandrum",
  age: 40
};

console.log(myData.name + " from " + myData.city + ", age " + myData.age);
// Anoop from Trivandrum, age 40

// Try each of these to see the compiler protect you:
// let bad1: Person = { name: "Ajay", city: "Chennai" };                    // missing 'age'
// let bad2: Person = { name: "Ajay", city: "Chennai", age: "forty" };      // wrong type
// let bad3: Person = { name: "Ajay", city: "Chennai", age: 30, pin: 1 };   // unknown property
The payoff to notice Type myData. in the Playground and wait — autocomplete offers exactly name, city, age and nothing else. That is the everyday benefit of interfaces, and it's why we'll define an Employee interface in Session 2 rather than passing loose objects around.

Drill D — an optional property (slide 14)

Try it yourself Take your Person interface and make age optional. Then create two objects — one with an age, one without — and confirm both compile.
▶ Show solution D 
interface PersonOpt {
  name: string;
  city: string;
  age?: number;          // the ? makes it optional
}

let withAge: PersonOpt    = { name: "Anoop", city: "Trivandrum", age: 40 };
let withoutAge: PersonOpt = { name: "Ajay",  city: "Chennai" };

console.log(withAge.age);      // 40
console.log(withoutAge.age);   // undefined  — absent, not an error

// The safe way to use an optional value:
if (withoutAge.age) {
  console.log("Age is " + withoutAge.age);
} else {
  console.log("Age not provided");
}
// Age not provided
Why the if guard matters An optional property may be undefined. Calling a method on it without checking produces the most common front-end error there is: "cannot read properties of undefined". Building the habit of guarding now will save you real debugging time in Session 3.

Drill E — a union type, used both ways (slide 15)

Try it yourself Change age so it accepts a number or a string. Create one object with 40 and one with "Forty" — both must compile. Then try true and confirm it does not.
▶ Show solution E 
interface PersonU {
  name: string;
  city: string;
  age: number | string;        // union: either type is allowed
}

let p1: PersonU = { name: "Anoop", city: "Trivandrum", age: 40 };      // OK
let p2: PersonU = { name: "Ajay",  city: "Chennai",    age: "Forty" }; // OK
// let p3: PersonU = { name: "Rekha", city: "Kochi",  age: true };     // ERROR

console.log(typeof p1.age);   // number
console.log(typeof p2.age);   // string

// Bonus — the form you'll actually use in Session 2:
let status: "Active" | "Inactive" = "Active";
// status = "active";     // ERROR — wrong case, caught at COMPILE time
Expected logs number then string. Note how typeof reports what's actually there at runtime, while the union describes what's allowed at compile time.

Drill F — looping a typed array (slide 16)

Try it yourself Create let arr = [10, 20, 30, 40]; and print its contents three ways: a classic for, a for...of, and a for...in. Predict the output of each before you run it.
▶ Show solution F 
let arr: number[] = [10, 20, 30, 40];

console.log("--- classic for ---");
for (let i = 0; i < arr.length; i++) {
  console.log(i + " -> " + arr[i]);
}

console.log("--- for...of  (VALUES) ---");
for (let value of arr) {
  console.log(value);            // 10, 20, 30, 40
}

console.log("--- for...in  (INDICES) ---");
for (let index in arr) {
  console.log(index + " holds " + arr[index]);   // "0" holds 10, ...
}
Expected output
--- classic for --- 0 -> 10 1 -> 20 2 -> 30 3 -> 40 --- for...of (VALUES) --- 10 20 30 40 --- for...in (INDICES) --- 0 holds 10 1 holds 20 2 holds 30 3 holds 40
Lock this in for...of → the values. for...in → the indices (as strings!). Angular's *ngFor="let emp of employees" uses of for exactly this reason.

Drill G — a typed tuple (slide 17)

Try it yourself Declare a tuple that holds, in this exact order: an employee id (number), a name (string), a designation (string) and a salary (number). Assign real values, print position 1, then deliberately swap the first two values and read the error.
▶ Show solution G 
let employee: [number, string, string, number];
employee = [1001, 'Anoop', 'Software Engineer', 25000.00];

console.log(employee);        // [1001, "Anoop", "Software Engineer", 25000]
console.log(employee[1]);     // Anoop   — TS knows position 1 is a string

// Both of these fail — and that's the point of a tuple:
// employee = ['Anoop', 1001, 'Software Engineer', 25000.00];   // wrong ORDER
// employee = [1001, 'Anoop', 'Software Engineer'];             // wrong LENGTH

// Compare with a plain array — flexible, but no per-position guarantee:
let loose: (number | string)[] = ['Anoop', 1001, 'Software Engineer', 25000.00];  // fine
The takeaway A tuple fixes both the length and the type at each position. It's precise but unreadable at scale — employee[2] tells you nothing. That's why real Angular code uses an interface with named fields, and tuples stay rare.
Bonus drill — a class (slide 18) If you're ahead: write a class Employee with id and name properties, a constructor, and a getDetails() method returning "1001 - Anoop". Then rewrite it using the constructor shorthand constructor(public id: number, public name: string) { } and confirm both behave identically. That shorthand is the line you'll write most often in Session 3.
TASK 2▶ Install the CLI & Scaffold Your First AppTheory slides 21–22
Goal Install the Angular CLI globally, generate a real project with one command, and see it running in your browser. This is the moment Angular stops being slides and starts being software.
Do this — step by step
  1. Open a terminal and cd to a folder you'll remember — e.g. cd Documents (avoid folders synced by OneDrive/Dropbox; they can slow the build dramatically and occasionally lock files).
  2. Install the CLI globally (one-time, takes a minute or two).
  3. Generate the project with ng new hello-world and answer the prompts.
  4. cd hello-world, then ng serve.
  5. Open http://localhost:4200 in your browser.

Common issues

SymptomCauseFix
ng: command not found / 'ng' is not recognized The global npm bin folder isn't on your PATH yet. Close and reopen the terminal. If it persists, run npm config get prefix and add that folder's bin to your PATH.
EACCES: permission denied during the global install No write access to the global npm folder (macOS/Linux). Use sudo npm install -g @angular/cli, or better, install Node via nvm so no sudo is needed.
Port 4200 is already in use Another ng serve is still running. Stop it with Ctrl+C, or run ng serve --port 4300.
npm ERR! network / install hangs No internet, or a corporate proxy is blocking the npm registry. npm config set proxy http://proxy:port and npm config set https-proxy http://proxy:port, then retry.
Browser shows "This site can't be reached" ng serve isn't actually running, or it failed to compile. Look back at the terminal. If you see red text, read the error — it names the file and line.
What just happened? Two commands gave you a fully-configured TypeScript project, a compiler, a bundler, a test harness, a linter config and a live-reloading development web server. Compare that with hand-assembling a front-end build — this is the same "convention over configuration" idea you met in Spring Boot, applied to the browser.

Trace the boot chain yourself

This is the single most clarifying five minutes of Session 1. Open these three files in order and find the highlighted line in each:

📄src/index.htmlread only — find <app-root>
<body>
  <app-root></app-root>      <!-- ← the ONLY thing in the body -->
</body>
📄src/app/app.component.tsread only — find the selector
@Component({
  selector: 'app-root',                  // ← matches the tag in index.html
  templateUrl: './app.component.html',
  styleUrls: ['./app.component.css']
})
export class AppComponent {
  title = 'hello-world';                 // ← the text you're about to change
}
📄src/app/app.module.tsread only — find bootstrap
@NgModule({
  declarations: [ AppComponent ],        // components that belong to this app
  imports:      [ BrowserModule ],       // Angular features this app uses
  providers:    [],                      // services (Session 3)
  bootstrap:    [ AppComponent ]         // ← start with THIS component
})
export class AppModule { }
Why this matters more than it looks A component's selector is just a custom HTML tag. Understanding that makes Session 2 trivial: you'll generate a component, drop <app-header></app-header> into another template, and watch it appear. That's the entire component tree mechanism.
TASK 4▶ Your First Edit — Prove Live Reload WorksTheory slide 25 (tail end)
Goal Confirm the development loop — edit → save → the browser updates by itself. This loop is what makes front-end work fast, and every remaining task in every remaining session depends on it.
Do this — step by step
  1. Make sure ng serve is still running and localhost:4200 is open. Put the editor and the browser side by side so you can watch both at once.
  2. Open src/app/app.component.html. Press Ctrl+A then Delete to remove all of the generated welcome markup.
  3. Paste the snippet below in its place.
  4. Save with Ctrl+S and watch the browser — do not refresh it manually.
📄src/app/app.component.htmlREPLACE the whole file
<h1>Welcome to {{ title }}!</h1>
<p>My first Angular edit — Session 1.</p>
Expected — the browser updates on its own
http://localhost:4200

Welcome to hello-world!

My first Angular edit — Session 1.

The word hello-world did not come from your HTML — it came from the title property in app.component.ts, delivered by {{ title }}. You have just used interpolation, the first of the four data bindings, which is the opening topic of Session 2.

Now change the data, not the template

Do this
  1. Open src/app/app.component.ts.
  2. Change title = 'hello-world'; to title = 'Angular Session 1';
  3. Save and watch the heading change — without touching the HTML at all.
Expected The heading now reads "Welcome to Angular Session 1!". This is the whole point of data binding: the template describes where the data goes, the class owns what the data is, and Angular keeps them in sync automatically.
Deliberately break it (30 seconds — genuinely worth doing) Change {{ title }} to {{ titel }}, save, and read the terminal: "Property 'titel' does not exist on type 'AppComponent'." Angular type-checks your templates, not just your TypeScript. Fix the typo and it recovers instantly. This is the single most useful error message you'll meet in the next three sessions — recognise it now.

Add a splash of style

📄src/app/app.component.csspaste — it's currently empty
h1 {
  color: #dd0031;
  font-family: system-ui, sans-serif;
}

p {
  color: #6e6e73;
}
Notice the scoping That h1 rule applies only inside this component. If Session 2 adds another component with an h1, it stays untouched. Angular achieves this by rewriting your selectors behind the scenes — inspect the element in DevTools and you'll see an attribute like _ngcontent-abc-1. Global styles, when you want them, go in src/styles.css.

▶ Glossary — terms you'll hear today
TermPlain-English meaning
SPASingle-Page Application — one HTML page loads once; JavaScript then swaps sections in and out
ComponentA reusable piece of UI = a TypeScript class + an HTML template + its own CSS
TemplateThe HTML file belonging to a component — what the user sees
SelectorThe custom HTML tag name that renders a component, e.g. <app-root>
DecoratorThe @Something({...}) syntax that attaches metadata to a class
Module (NgModule)A manifest grouping components, directives and services that belong together
InterpolationShowing a class property in a template using {{ }}
InterfaceA TypeScript description of an object's shape — which properties, of which types
Union type"One of these types", written with a pipe: number | string
TupleA fixed-length array with a specific type at each position
Transpile / compileTranslating TypeScript into the JavaScript the browser actually runs
npmNode Package Manager — the Maven of the JavaScript world
CLICommand Line Interface — Angular's ng tool
node_modulesWhere npm puts downloaded libraries. Never edit it, never commit it
Live reload / HMRThe dev server rebuilding and refreshing the browser automatically when you save
