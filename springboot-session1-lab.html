⚠️ The Golden Rule of Spring Boot packages

Spring can only manage classes it is able to find. It searches starting from the package that holds your main application class, and works downward into sub-packages. It never looks sideways or upward.

Every class you create must live in the same package as the main class, or in a sub-package of it.

In today's project the base package is com.tcs.training.demo, so your classes go in com.tcs.training.demo.controller, com.tcs.training.demo.service, and so on. Put a controller in com.tcs.training.controller instead — one word shorter — and Spring will never see it. The app still starts with no error, but every request returns the Whitelabel Error Page (404). That is the trap; the file banners in this sheet spell out the full path of every file so you can't fall into it.

LAB 3GET▶ Your First REST Endpoint
Concept — what the two annotations do @RestController tells Spring: "this class handles web requests, and whatever my methods return is the response body" (rather than the name of an HTML page to render). @GetMapping("/hello") then says: "when an HTTP GET arrives for the path /hello, call this method." Together, they're all you need for a working endpoint.
Do this — step by step
  1. In the IDE project tree, find the package com.tcs.training.demo — the one containing DemoApplication.java.
  2. Right-click it → New → Package. Name it com.tcs.training.demo.controller (type the full name; most IDEs pre-fill the com.tcs.training.demo. part, so you may only need to add controller).
  3. Confirm the new controller folder appears next to DemoApplication.java, not somewhere above it. ✅
  4. Right-click controller → New → Class. Name it HelloController — capital H and C, and no .java extension. Click Finish.
  5. The IDE opens a nearly-empty file. Select everything (Ctrl+A, or Cmd+A on Mac), delete it, then paste the whole file below.
  6. Restart the app. Stop the previous run first (the red square), then run DemoApplication again. Spring only scans for classes at startup, so a new controller is invisible until you restart.
  7. Open http://localhost:8080/hello in your browser.

🚨 Got a Whitelabel Error Page instead? Check these, in order
  1. Did you restart the app? By far the most common cause. New classes are only picked up at startup.
  2. Is your package right? The first line of HelloController.java must read package com.tcs.training.demo.controller; — the base package plus .controller. If it's missing the .demo part, Spring never scanned it.
  3. Is @RestController present and spelled correctly, directly above public class HelloController?
  4. Does the path start with a slash? @GetMapping("/hello"), not ("hello").
  5. Check the startup log. With logging.level.org.springframework.web=DEBUG in application.properties, Spring prints every registered mapping. If /hello isn't in that list, the class was never found — go back to point 2.
Try it — learn by breaking things (2 minutes, worth it) Comment out the @RestController line (put // in front of it), restart, and reload /hello. You'll get the Whitelabel 404 — because without the annotation Spring never registered the class, even though the file compiles perfectly. Now put it back. You have just seen, first-hand, that an annotation is what makes a class visible to the framework.
LAB 4GET▶ Reading Values From the URL
Concept — two places a value can hide in a URL A fixed response is not very useful. Real endpoints take input, and it arrives in one of two places:
  • @PathVariable — the value is part of the path: /hello/Purvam. Declare the slot with braces in the mapping: @GetMapping("/hello/{name}"). Use this to identify which thing you want.
  • @RequestParam — the value comes after a ?: /greet?name=Purvam. Use this to filter, sort, or pass optional extras.
Do this — step by step
  1. Open the HelloController.java you created in Lab 3.
  2. Select all and paste the whole updated file below over it — it keeps the two old methods and adds three new ones.
  3. Stop the app, run it again.
  4. Try each of the URLs in the expected-output table.
📄src/main/java/com/tcs/training/demo/controller/HelloController.javareplace the whole file
package com.tcs.training.demo.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String sayHello() {
        return "Hello from Spring Boot!";
    }

    @GetMapping("/welcome")
    public String welcome() {
        return "Welcome to the Spring Boot session!";
    }

    // ---- NEW: a value taken from INSIDE the path ----
    // GET /hello/Purvam        ->  Hello, Purvam!
    @GetMapping("/hello/{name}")
    public String helloName(@PathVariable String name) {
        return "Hello, " + name + "!";
    }

    // ---- NEW: a value taken from AFTER the ? ----
    // GET /greet?name=Purvam   ->  Greetings, Purvam!
    // GET /greet               ->  Greetings, Guest!   (defaultValue kicks in)
    @GetMapping("/greet")
    public String greet(@RequestParam(defaultValue = "Guest") String name) {
        return "Greetings, " + name + "!";
    }

    // ---- NEW: two path variables and simple maths ----
    // GET /add/7/5             ->  7 + 5 = 12
    @GetMapping("/add/{a}/{b}")
    public String add(@PathVariable int a, @PathVariable int b) {
        return a + " + " + b + " = " + (a + b);
    }
}
Now run it
  1. Stop the app, then run DemoApplication again.
  2. Visit each URL in the table below, substituting your own name.
Expected output
URLResponseWhy
/hello/PurvamHello, Purvam!@PathVariable captured Purvam from the path

Notice what Spring did for free in /add/7/5 A URL is always just text — "7" arrives as characters, not a number. You declared the parameter as int, and Spring converted it for you. Now try /add/seven/5: you get a 400 Bad Request, because "seven" can't become an int. Spring validated the input type without you writing a single check.

LAB 5▶ Dependency Injection in Action
Concept — what we're actually demonstrating So far all our logic sat in the controller. That's fine for one line, but real business rules belong in a service. So we need the controller to use a service object — and the question is who creates that object. We will not write new GreetingService(). Instead we'll mark the service with @Service so Spring creates it, and let the controller ask for one in its constructor. Spring matches them by type and hands it over. That handover is dependency injection.
Do this — step by step
  1. Right-click the package com.tcs.training.demo → New → Package → name it com.tcs.training.demo.service. It must land next to controller and DemoApplication.java.
  2. In that new service package: New → Class named GreetingService. Paste file 1 below.
  3. In the existing controller package: New → Class named GreetController. Paste file 2 below.
  4. Stop the app, run it again.
  5. Visit http://localhost:8080/api/greet/Purvam.

package com.tcs.training.demo.service;

import org.springframework.stereotype.Service;

// @Service tells Spring: "create ONE of these at startup and keep it."
// The object Spring creates and holds is what we call a BEAN.
@Service
public class GreetingService {

    public String greet(String name) {
        return "Hello, " + name + "! (this text came from GreetingService)";
    }

    public String farewell(String name) {
        return "Goodbye, " + name + ". See you next session!";
    }
}
📄src/main/java/com/tcs/training/demo/controller/GreetController.javafile 2 of 2 — paste the WHOLE file
package com.tcs.training.demo.controller;

import com.tcs.training.demo.service.GreetingService;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api")     // every path in this class now starts with /api
public class GreetController {

    // 'final' means: set once in the constructor, never reassigned.
    private final GreetingService greetingService;

    // CONSTRUCTOR INJECTION.
    // Spring sees this constructor needs a GreetingService, finds the bean
    // it created from the @Service class, and passes it in automatically.
    // Note: no @Autowired needed — there is only one constructor.
    public GreetController(GreetingService greetingService) {
        this.greetingService = greetingService;
    }

    // GET /api/greet/Purvam
    @GetMapping("/greet/{name}")
    public String greet(@PathVariable String name) {
        return greetingService.greet(name);      // the controller delegates
    }

    // GET /api/bye/Purvam
    @GetMapping("/bye/{name}")
    public String bye(@PathVariable String name) {
        return greetingService.farewell(name);
    }
}
Now run it
  1. Stop the app, then run DemoApplication again.
  2. Visit http://localhost:8080/api/greet/Purvam
  3. Then http://localhost:8080/api/bye/Purvam
Expected output
URLResponse
/api/greet/PurvamHello, Purvam! (this text came from GreetingService)
/api/bye/PurvamGoodbye, Purvam. See you next session!
Notice @RequestMapping("/api") on the class Putting @RequestMapping at class level sets a prefix for every method inside. So @GetMapping("/greet/{name}") actually serves /api/greet/{name}. This is how real APIs group related endpoints under a common base path — and you'll use it constantly from Session 2 onwards.

BONUS 1▶ Return JSON Instead of Plain Text
Concept Real APIs return structured data, not sentences. In Spring Boot you don't build JSON by hand: you return a Java object, and a library called Jackson — already on your classpath courtesy of spring-boot-starter-web — converts it to JSON automatically. One rule: the class needs getters, because that's how Jackson reads the values out.
Do this — step by step
  1. Create the package com.tcs.training.demo.model (again, right next to controller and service).
  2. In it, create the class Greeting and paste file 1.
  3. In the controller package, create JsonController and paste file 2.
  4. Restart, then visit http://localhost:8080/api/json/hello/Purvam.
📄src/main/java/com/tcs/training/demo/model/Greeting.javafile 1 of 2 — paste the WHOLE file
package com.tcs.training.demo.model;

import java.time.LocalDateTime;

// A plain data-carrying class. Jackson turns it into JSON using the getters.
public class Greeting {

    private String message;
    private String recipient;
    private LocalDateTime timestamp;

    // A no-argument constructor is required by Jackson when reading JSON in.
    public Greeting() {
    }

    public Greeting(String message, String recipient) {
        this.message = message;
        this.recipient = recipient;
        this.timestamp = LocalDateTime.now();
    }

    // ---- Getters: Jackson uses these to build the JSON ----
    public String getMessage() {
        return message;
    }

    public String getRecipient() {
        return recipient;
    }

    public LocalDateTime getTimestamp() {
        return timestamp;
    }

    // ---- Setters: used when JSON is read back INTO an object ----
    public void setMessage(String message) {
        this.message = message;
    }

    public void setRecipient(String recipient) {
        this.recipient = recipient;
    }

    public void setTimestamp(LocalDateTime timestamp) {
        this.timestamp = timestamp;
    }
}
📄src/main/java/com/tcs/training/demo/controller/JsonController.javafile 2 of 2 — paste the WHOLE file
package com.tcs.training.demo.controller;

import com.tcs.training.demo.model.Greeting;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/json")
public class JsonController {

    // Returning an OBJECT -> Spring converts it to a JSON object
    // GET /api/json/hello/Purvam
    @GetMapping("/hello/{name}")
    public Greeting helloJson(@PathVariable String name) {
        return new Greeting("Hello from Spring Boot!", name);
    }

    // Returning a LIST -> Spring converts it to a JSON array
    // GET /api/json/all
    @GetMapping("/all")
    public List<Greeting> allGreetings() {
        return List.of(
                new Greeting("Hello!", "Purvam"),
                new Greeting("Namaste!", "Team"),
                new Greeting("Welcome!", "Everyone")
        );
    }
}
Expected output — GET /api/json/hello/Purvam 
{
  "message": "Hello from Spring Boot!",
  "recipient": "Purvam",
  "timestamp": "2026-09-05T10:32:14.882"
}
And GET /api/json/all returns a JSON array — square brackets containing three objects.
Three things to notice
  1. The JSON field names came from the getter names — getMessage() became "message". Rename the getter and the JSON key changes with it.
  2. You never wrote "{" or a comma. Returning the object was enough.
  3. Returning a List produced a JSON array automatically. This is exactly how you'll return "all students" in Session 2.
Prettier output in the browser Raw JSON is dense on one line. Install a "JSON Formatter" browser extension, or better, use Swagger UI — which formats it automatically and is the tool we adopt properly in Session 2.

▶ 🔧 Troubleshooting Guide — every error you might hit today
SymptomMost likely causeFix
Whitelabel Error Page, 404, on a URL you just created You didn't restart the app (most common), or the class sits outside the base package, or @RestController is missing. Restart first. Then check the class's package line begins with com.tcs.training.demo. Then check the annotation. Then confirm the mapping path starts with /.
required a bean of type '…' that could not be found The class being injected has no stereotype annotation, or lives outside the scanned packages. Add @Service / @Component / @Repository, and verify its package is under com.tcs.training.demo.
Port 8080 was already in use A previous run is still going, or another program owns the port. Stop the old run. Or set server.port=8081. To find the culprit: lsof -i :8080 (Mac/Linux) or netstat -ano | findstr :8080 (Windows).
Ambiguous mapping. Cannot map … method Two methods claim the same HTTP verb and the same path. Make each verb+path combination unique. Remember a class-level @RequestMapping counts as part of the path.
405 Method Not Allowed The path exists, but not for that verb — e.g. sending POST to a @GetMapping. Match the annotation to the verb you're sending. Note a browser address bar can only send GET.
400 Bad Request on /add/seven/5 Spring couldn't convert the text "seven" into an int. Working as intended — pass a number. (This is free input validation.)
Cannot resolve symbol 'GreetingService' in the IDE Missing import, or you're referring to a class in a different package. Add import com.tcs.training.demo.service.GreetingService; — or press Alt+Enter (IntelliJ) / Ctrl+Shift+O (Eclipse) to auto-import.
Changes to a Java file seem to have no effect The app wasn't restarted. Spring scans classes only at startup. Always stop and re-run after editing. (Adding spring-boot-devtools gives automatic restarts.)
invalid target release: 17 / class file has wrong version Project's Java version is higher than your installed JDK. Check java -version and set the matching number in pom.xml → <java.version>.

▶ 📖 Glossary — every term you heard today
TermPlain-English meaning
FrameworkCode that runs your code. It owns the main flow and calls your methods at the right moments (unlike a library, which you call).
BeanAn ordinary Java object that Spring created and holds on to — not one you made with new. One instance per app by default.
IoC containerThe single big object Spring builds at startup that holds every bean and knows how they connect. Also called the application context.
Inversion of ControlThe framework calls your code instead of your code calling the framework. Control of the flow is inverted.
DependencyAn object that another object needs to do its job. A controller depends on a service.
Dependency Injection (DI)Objects don't create what they need — it's handed to them from outside (by Spring), usually through the constructor.
Component scanningSpring's startup search for annotated classes, starting at the main class's package and going downward. The golden rule comes from this.
Base packageThe package your main class sits in. Everything you write must live in it or below it.
Auto-configurationBoot inspecting which libraries are present and creating sensible beans for them — always overridable by defining your own.
ClasspathThe full list of code available at runtime: your classes plus every library JAR.
StarterOne dependency that pulls in a whole coherent set of libraries at versions verified to work together.
Embedded serverTomcat living inside your application, so you run the app instead of deploying to a server.
DispatcherServletSpring's traffic cop. Receives every request and decides which of your methods should handle it.
EndpointOne combination of HTTP verb + path that your app answers, e.g. GET /hello.
RESTA style of API design: URLs name resources (nouns), HTTP verbs say what to do to them, and the server keeps no session state.
JSONThe text format APIs use to exchange data. Spring converts your objects to and from it automatically.
JacksonThe library that does that JSON conversion. Included with spring-boot-starter-web.
POM"Project Object Model" — the pom.xml file listing your dependencies and build settings.
Whitelabel Error PageSpring Boot's plain default error page. On a URL you just wrote, it almost always means the endpoint isn't registered.
ActuatorA starter that adds ready-made health, metrics, beans and mappings endpoints for monitoring and debugging.
