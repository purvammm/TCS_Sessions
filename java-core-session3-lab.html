import java.util.ArrayList;
import java.util.List;

public class ListBasics {

    public static void main(String[] args) {

        // Declare the INTERFACE, instantiate the CLASS  (theory slide 6)
        List<Account> portfolio = new ArrayList<>();

        portfolio.add(new SavingsAccount     ("AC1001", "Priya Sharma",  50000));
        portfolio.add(new CurrentAccount     ("AC1002", "Rahul Verma",   80000, 25000));
        portfolio.add(new FixedDepositAccount("AC1003", "Anita Desai",  200000, 12));
        portfolio.add(new SalaryAccount      ("AC1004", "Vikram Rao",     1200));

        System.out.println("size() = " + portfolio.size());

        // 1. Add a fifth - no ceremony at all
        portfolio.add(new SavingsAccount("AC1005", "Deepa Iyer", 30000));
        System.out.println("after add, size() = " + portfolio.size());

        // 2. Insert at a position (everything after shifts right)
        portfolio.add(0, new SalaryAccount("AC1000", "Meera Nair", 5000));
        System.out.println("after insert at 0, size() = " + portfolio.size());

        // 3. Remove by index
        portfolio.remove(1);
        System.out.println("after remove(1), size() = " + portfolio.size());

        // 4. Read and replace by index
        System.out.println("get(0) = " + portfolio.get(0).getAccountNumber());

        System.out.println("\n--- the whole portfolio ---");
        for (Account a : portfolio) {
            System.out.println(a);
        }

        // 5. Total balance - polymorphic call inside a List loop
        double total = 0;
        for (Account a : portfolio) total += a.getBalance();
        System.out.printf("%nTotal across %d accounts: %.2f%n", portfolio.size(), total);

        // 6. Swap the implementation - ONE word changes, nothing else
        List<Account> asLinked = new java.util.LinkedList<>(portfolio);
        System.out.println("Same code, LinkedList: size " + asLinked.size());
    }
}

TASK 2▶ Generics & the remove() TrapTheory slides 7–8
Goal See raw types fail at runtime versus generics failing at compile time, then hit the single most notorious overload trap in the entire Java library.
📄GenericsLab.javacreate this file
import java.util.ArrayList;
import java.util.List;

public class GenericsLab {

    @SuppressWarnings({"rawtypes", "unchecked"})
    public static void main(String[] args) {

        // ===== 1. RAW type - no type safety =====
        System.out.println("--- raw list ---");
        List raw = new ArrayList();
        raw.add("Priya");
        raw.add(42);                    // compiler allows a mixed bag
        raw.add(true);
        System.out.println("raw = " + raw);

        try {
            String s = (String) raw.get(1);      // cast an Integer to String
            System.out.println(s);
        } catch (ClassCastException e) {
            System.out.println("ClassCastException at RUNTIME: " + e.getMessage());
        }

        // ===== 2. GENERIC - impossible to get wrong =====
        System.out.println("\n--- generic list ---");
        List<String> names = new ArrayList<>();
        names.add("Priya");
        // names.add(42);               // UNCOMMENT: compile error, not runtime
        String safe = names.get(0);     // no cast needed
        System.out.println("safe = " + safe);

        // ===== 3. THE remove() TRAP =====
        System.out.println("\n--- the remove() trap ---");
        List<Integer> nums = new ArrayList<>(List.of(10, 20, 30, 40, 50));
        System.out.println("start          : " + nums);

        nums.remove(2);                          // remove(int index) -> removes 30
        System.out.println("remove(2)      : " + nums);

        nums.remove(Integer.valueOf(20));        // remove(Object) -> removes VALUE 20
        System.out.println("remove(val 20) : " + nums);

        // ===== 4. Autoboxing =====
        System.out.println("\n--- autoboxing ---");
        List<Integer> boxed = new ArrayList<>();
        boxed.add(5);                   // int 5 -> Integer.valueOf(5), silently
        int back = boxed.get(0);        // Integer -> int, silently
        System.out.println("boxed = " + boxed + ", unboxed back = " + back);

        // The classic gotcha: == on boxed values above 127
        Integer a = 1000, b = 1000;
        System.out.println("a == b      -> " + (a == b) + "   (reference compare!)");
        System.out.println("a.equals(b) -> " + a.equals(b) + "   (value compare)");
    }
}
Expected output
--- raw list --- raw = [Priya, 42, true] ClassCastException at RUNTIME: class java.lang.Integer cannot be cast to class java.lang.String --- generic list --- safe = Priya --- the remove() trap --- start : [10, 20, 30, 40, 50] remove(2) : [10, 20, 40, 50] ← removed INDEX 2 (the value 30) remove(val 20) : [10, 40, 50] ← removed the VALUE 20 --- autoboxing --- boxed = [5], unboxed back = 5 a == b -> false (reference compare!) a.equals(b) -> true (value compare)
Why a == b is false for 1000 but true for 100 Java caches Integer objects from −128 to 127, so small values are literally the same object. Above that range you get distinct objects and == compares references. Never use == on boxed types — always equals(). Try changing 1000 to 100 and watch the answer flip; it's a favourite interview question.
Prove generics work Uncomment names.add(42); and compile. You should get incompatible types: int cannot be converted to String — caught at compile time, exactly where you want it.
TASK 3▶ ArrayList vs LinkedList — Measure ItTheory slides 9–12
Goal Stop taking Big-O on trust. Time it yourself and see the O(n²) disaster with your own eyes — then see where LinkedList genuinely wins.
📄PerfLab.javacreate this file
import java.util.ArrayList;
import java.util.LinkedList;
import java.util.List;

public class PerfLab {

    static final int N = 50_000;

    public static void main(String[] args) {
        List<Integer> arrayList  = new ArrayList<>();
        List<Integer> linkedList = new LinkedList<>();
        for (int i = 0; i < N; i++) { arrayList.add(i); linkedList.add(i); }

        System.out.println("N = " + N + "\n");

        // ===== TEST 1: indexed get(i) - the O(n^2) trap =====
        System.out.println("TEST 1: loop with get(i)");
        System.out.printf("  ArrayList  : %6d ms%n", time(() -> {
            long sum = 0;
            for (int i = 0; i < arrayList.size(); i++) sum += arrayList.get(i);
        }));
        System.out.printf("  LinkedList : %6d ms   <-- walks the chain every time%n", time(() -> {
            long sum = 0;
            for (int i = 0; i < linkedList.size(); i++) sum += linkedList.get(i);
        }));

        // ===== TEST 2: the SAME data, but for-each =====
        System.out.println("\nTEST 2: for-each (uses the iterator)");
        System.out.printf("  ArrayList  : %6d ms%n", time(() -> {
            long sum = 0;
            for (int v : arrayList) sum += v;
        }));
        System.out.printf("  LinkedList : %6d ms   <-- now competitive!%n", time(() -> {
            long sum = 0;
            for (int v : linkedList) sum += v;
        }));

        // ===== TEST 3: inserting at the FRONT - LinkedList's home turf =====
        System.out.println("\nTEST 3: 50,000 inserts at index 0");
        System.out.printf("  ArrayList  : %6d ms   <-- shifts everything, every time%n", time(() -> {
            List<Integer> l = new ArrayList<>();
            for (int i = 0; i < N; i++) l.add(0, i);
        }));
        System.out.printf("  LinkedList : %6d ms%n", time(() -> {
            List<Integer> l = new LinkedList<>();
            for (int i = 0; i < N; i++) l.add(0, i);
        }));

        // ===== TEST 4: pre-sizing an ArrayList =====
        System.out.println("\nTEST 4: 1,000,000 appends");
        System.out.printf("  default capacity  : %6d ms%n", time(() -> {
            List<Integer> l = new ArrayList<>();
            for (int i = 0; i < 1_000_000; i++) l.add(i);
        }));
        System.out.printf("  pre-sized         : %6d ms%n", time(() -> {
            List<Integer> l = new ArrayList<>(1_000_000);
            for (int i = 0; i < 1_000_000; i++) l.add(i);
        }));
    }

    static long time(Runnable task) {
        long start = System.currentTimeMillis();
        task.run();
        return System.currentTimeMillis() - start;
    }
}
Now run it
  1. javac PerfLab.java
  2. java PerfLab — test 1 on the LinkedList will take a few seconds. Be patient; that's the lesson.
Typical output — your exact numbers will differ
N = 50000 TEST 1: loop with get(i) ArrayList : 2 ms LinkedList : 3841 ms <-- walks the chain every time TEST 2: for-each (uses the iterator) ArrayList : 3 ms LinkedList : 4 ms <-- now competitive! TEST 3: 50,000 inserts at index 0 ArrayList : 412 ms <-- shifts everything, every time LinkedList : 3 ms TEST 4: 1,000,000 appends default capacity : 31 ms pre-sized : 12 ms
Read these four results carefully — this is the whole task Test 1: the same logical loop is ~1,000× slower on a LinkedList. That's O(n²) versus O(n), and it's a real bug people ship.
Test 2: identical data, identical work — but for-each uses the iterator, so LinkedList is fine. How you loop matters more than what you loop over.
Test 3: LinkedList's genuine win — front insertion, ~100× faster.
Test 4: pre-sizing an ArrayList is free performance when you know the size.

TASK 4▶ Iteration & ConcurrentModificationExceptionTheory slides 13–14
Goal Trigger ConcurrentModificationException deliberately, then fix it three different ways. Everyone hits this exception once — better here than in production.
📄IterationLab.javacreate this file
import java.util.ArrayList;
import java.util.ConcurrentModificationException;
import java.util.Iterator;
import java.util.List;

public class IterationLab {

    public static void main(String[] args) {

        // ===== The four ways to iterate =====
        List<String> names = new ArrayList<>(List.of("Priya", "Rahul", "Anita", "Ravi"));

        System.out.println("1. classic for (index available):");
        for (int i = 0; i < names.size(); i++) System.out.println("   " + i + ": " + names.get(i));

        System.out.println("2. for-each (the default):");
        for (String n : names) System.out.println("   " + n);

        System.out.println("3. Iterator (can remove):");
        Iterator<String> it = names.iterator();
        while (it.hasNext()) System.out.println("   " + it.next());

        System.out.println("4. forEach + method reference:");
        names.forEach(n -> System.out.println("   " + n));

        // ===== BREAK IT: remove inside a for-each =====
        System.out.println("\n=== The bug ===");
        List<String> bad = new ArrayList<>(List.of("Priya", "Rahul", "Anita", "Ravi"));
        try {
            for (String n : bad) {
                if (n.startsWith("R")) {
                    bad.remove(n);              // structural change during iteration
                }
            }
            System.out.println("  no exception?! " + bad);
        } catch (ConcurrentModificationException e) {
            System.out.println("  ConcurrentModificationException - as expected");
        }

        // ===== FIX A: removeIf - one line, always correct =====
        System.out.println("\n=== Fix A: removeIf ===");
        List<String> fixA = new ArrayList<>(List.of("Priya", "Rahul", "Anita", "Ravi"));
        fixA.removeIf(n -> n.startsWith("R"));
        System.out.println("  " + fixA);

        // ===== FIX B: Iterator.remove() =====
        System.out.println("=== Fix B: Iterator.remove() ===");
        List<String> fixB = new ArrayList<>(List.of("Priya", "Rahul", "Anita", "Ravi"));
        Iterator<String> iter = fixB.iterator();
        while (iter.hasNext()) {
            if (iter.next().startsWith("R")) iter.remove();
        }
        System.out.println("  " + fixB);

        // ===== FIX C: collect, then removeAll =====
        System.out.println("=== Fix C: collect then removeAll ===");
        List<String> fixC = new ArrayList<>(List.of("Priya", "Rahul", "Anita", "Ravi"));
        List<String> doomed = new ArrayList<>();
        for (String n : fixC) if (n.startsWith("R")) doomed.add(n);
        fixC.removeAll(doomed);
        System.out.println("  " + fixC);

        // ===== set() is NOT structural - this is safe =====
        System.out.println("\n=== set() during a classic for is fine ===");
        List<String> upper = new ArrayList<>(List.of("priya", "rahul", "anita"));
        for (int i = 0; i < upper.size(); i++) upper.set(i, upper.get(i).toUpperCase());
        System.out.println("  " + upper);
    }
}
Expected output (abridged)
=== The bug === ConcurrentModificationException - as expected === Fix A: removeIf === [Priya, Anita] === Fix B: Iterator.remove() === [Priya, Anita] === Fix C: collect then removeAll === [Priya, Anita] === set() during a classic for is fine === [PRIYA, RAHUL, ANITA]
A subtlety worth knowing Try removing the second-to-last element in a for-each. Sometimes it doesn't throw at all — it silently skips an element instead, because the iterator's hasNext() happens to return false early. That's worse than the exception, and it's precisely why you should never rely on getting an error. Use removeIf.

import java.util.ArrayList;
import java.util.Collections;
import java.util.Comparator;
import java.util.List;

public class SortLab {

    public static void main(String[] args) {
        List<Account> accounts = new ArrayList<>(List.of(
            new SavingsAccount     ("AC1001", "Priya Sharma",  50000),
            new CurrentAccount     ("AC1002", "Rahul Verma",   80000, 25000),
            new FixedDepositAccount("AC1003", "Anita Desai",  200000, 12),
            new SalaryAccount      ("AC1004", "Vikram Rao",     1200),
            new SavingsAccount     ("AC1005", "Deepa Iyer",    30000),
            new SavingsAccount     ("AC1006", "Arjun Mehta",   80000)
        ));

        print("1. Insertion order", accounts);

        // ===== COMPARABLE: the natural order, built into the class =====
        Collections.sort(accounts);
        print("2. Natural order (balance ascending) - Comparable", accounts);

        // ===== COMPARATOR: any order, without editing Account =====
        accounts.sort(Comparator.comparingDouble(Account::getBalance).reversed());
        print("3. Balance DESCENDING - Comparator.reversed()", accounts);

        accounts.sort(Comparator.comparing(Account::getHolder));
        print("4. Holder name A-Z", accounts);

        accounts.sort(Comparator.comparing(Account::accountType)
                                .thenComparing(Comparator.comparingDouble(Account::getBalance)
                                                         .reversed()));
        print("5. Type, then balance descending - thenComparing()", accounts);

        accounts.sort(Comparator.comparing((Account a) -> a.getHolder().length())
                                .thenComparing(Account::getHolder));
        print("6. Name LENGTH, then alphabetical", accounts);

        // A lambda, for when the factory methods aren't enough
        accounts.sort((a, b) -> b.getAccountNumber().compareTo(a.getAccountNumber()));
        print("7. Account number descending - raw lambda", accounts);

        // ===== Collections utility methods =====
        System.out.println("\n--- Collections utilities ---");
        System.out.println("max by balance : " + Collections.max(accounts).getHolder());
        System.out.println("min by balance : " + Collections.min(accounts).getHolder());
        Collections.reverse(accounts);
        System.out.println("after reverse, first: " + accounts.get(0).getAccountNumber());
        Collections.shuffle(accounts);
        System.out.println("after shuffle, first: " + accounts.get(0).getAccountNumber());

        // binarySearch REQUIRES a sorted list
        Collections.sort(accounts);
        Account target = accounts.get(3);
        System.out.println("binarySearch found index: " + Collections.binarySearch(accounts, target));
    }

    static void print(String title, List<Account> accounts) {
        System.out.println("\n=== " + title + " ===");
        for (Account a : accounts) System.out.println("  " + a);
    }
}

TASK 6▶ The Immutability TrapsTheory slide 17
Goal Hit all three immutability traps in one file so you recognise UnsupportedOperationException instantly when it appears in real code.
📄ImmutableTraps.javacreate this file
import java.util.ArrayList;
import java.util.Arrays;
import java.util.Collections;
import java.util.List;

public class ImmutableTraps {

    public static void main(String[] args) {

        // ===== TRAP 1: List.of() is fully IMMUTABLE =====
        System.out.println("TRAP 1: List.of()");
        List<String> fixed = List.of("a", "b", "c");
        attempt("add",  () -> fixed.add("d"));
        attempt("set",  () -> fixed.set(0, "z"));

        // ===== TRAP 2: Arrays.asList() is FIXED-SIZE but mutable =====
        System.out.println("\nTRAP 2: Arrays.asList()");
        String[] array = {"a", "b", "c"};
        List<String> view = Arrays.asList(array);
        attempt("add",  () -> view.add("d"));
        attempt("set",  () -> view.set(0, "z"));      // this one WORKS
        System.out.println("  after set: " + view);
        System.out.println("  the BACKING ARRAY changed too: " + Arrays.toString(array));

        // ===== TRAP 3: unmodifiableList is a VIEW, not a copy =====
        System.out.println("\nTRAP 3: unmodifiableList is a live view");
        List<String> backing  = new ArrayList<>(List.of("a", "b"));
        List<String> readOnly = Collections.unmodifiableList(backing);
        attempt("add via readOnly", () -> readOnly.add("c"));
        backing.add("c");                            // but the ORIGINAL still can
        System.out.println("  readOnly now shows: " + readOnly + "  <-- it changed!");

        // ===== THE FIX: copyOf makes a real, independent snapshot =====
        System.out.println("\nTHE FIX: List.copyOf() is a true snapshot");
        List<String> snapshot = List.copyOf(backing);
        backing.add("d");
        System.out.println("  backing  : " + backing);
        System.out.println("  snapshot : " + snapshot + "  <-- unaffected");

        // ===== And how to get a genuinely mutable copy =====
        System.out.println("\nMutable copy of an immutable list:");
        List<String> mutable = new ArrayList<>(List.of("a", "b", "c"));
        mutable.add("d");
        System.out.println("  " + mutable);
    }

    static void attempt(String label, Runnable action) {
        try {
            action.run();
            System.out.println("  " + label + ": OK");
        } catch (UnsupportedOperationException e) {
            System.out.println("  " + label + ": UnsupportedOperationException");
        }
    }
}
Expected output

The one to really remember Trap 3. Handing someone an unmodifiableList does not give them a stable snapshot — it gives them a read-only window onto data you can still change underneath them. When you want a true snapshot, use List.copyOf(...). This matters directly for the defensive-copy work in Task 8.

import java.util.ArrayList;
import java.util.List;
import java.util.Objects;

public class Customer {

    private final String customerId;
    private final String name;

    // AGGREGATION: accounts have their own lifecycle. Note the list is created
    // here but the Account objects are passed IN from outside.
    private final List<Account> accounts = new ArrayList<>();

    public Customer(String customerId, String name) {
        this.customerId = customerId;
        this.name = name;
    }

    public void addAccount(Account account) {
        Objects.requireNonNull(account, "account must not be null");
        accounts.add(account);
    }

    // Behaviour, not raw data
    public double totalWealth() {
        double total = 0;
        for (Account a : accounts) total += a.getBalance();   // polymorphic
        return total;
    }

    public int accountCount() { return accounts.size(); }

    // DEFENSIVE COPY - callers cannot clear our list
    public List<Account> getAccounts() { return List.copyOf(accounts); }

    public String getName()       { return name; }
    public String getCustomerId() { return customerId; }

    @Override
    public String toString() {
        return String.format("%s (%s): %d account(s), total %.2f",
                             name, customerId, accounts.size(), totalWealth());
    }
}

    private final List<Customer> customers;

        this.name = name;
        this.customers = new ArrayList<>(customers);   // defensive copy of the LIST

        double total = 0;

        return total;
    }

    public List<Customer> getCustomers() { return List.copyOf(customers); }
    public String getName()              { return name; }
}

        System.out.println("\n--- aggregation: parts outlive the whole ---");

        priya = null;                          // the Customer is gone
        System.out.println("Customer reference cleared, but the account still exists:");
        System.out.println("   " + a1);
        System.out.println("   balance still readable: " + a1.getBalance());

        // ===== DEFENSIVE COPY proof =====
        System.out.println("\n--- defensive copy: outsiders cannot break us ---");

            System.out.println("clear() rejected - UnsupportedOperationException");
        }
        System.out.println("Rahul's account count AFTER the attack: " + rahul.accountCount());

📄CountingLab.javacreate this file
import java.util.ArrayList;
import java.util.Collection;
import java.util.List;

// ===== THE BROKEN VERSION: inheritance used for reuse =====
class InheritedCounter<E> extends ArrayList<E> {
    private int addCount = 0;

    @Override
    public boolean add(E e) {
        addCount++;
        return super.add(e);
    }

    @Override
    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return super.addAll(c);      // internally calls add() for EACH element!
    }

    public int getAddCount() { return addCount; }
}

// ===== THE FIXED VERSION: composition =====
class ComposedCounter<E> {
    private final List<E> inner = new ArrayList<>();
    private int addCount = 0;

    public boolean add(E e) {
        addCount++;
        return inner.add(e);
    }

    public boolean addAll(Collection<? extends E> c) {
        addCount += c.size();
        return inner.addAll(c);      // inner's internals cannot reach OUR add()
    }

    public int getAddCount() { return addCount; }
    public int size()        { return inner.size(); }
    public List<E> asList()  { return List.copyOf(inner); }
}

public class CountingLab {

    public static void main(String[] args) {

        System.out.println("=== Inheritance version ===");
        InheritedCounter<String> bad = new InheritedCounter<>();
        bad.addAll(List.of("a", "b", "c"));
        System.out.println("  added 3 items");
        System.out.println("  size()        = " + bad.size());
        System.out.println("  getAddCount() = " + bad.getAddCount() + "   <-- WRONG");

        System.out.println("\n=== Composition version ===");
        ComposedCounter<String> good = new ComposedCounter<>();
        good.addAll(List.of("a", "b", "c"));
        System.out.println("  added 3 items");
        System.out.println("  size()        = " + good.size());
        System.out.println("  getAddCount() = " + good.getAddCount() + "   <-- CORRECT");

        // And the OTHER problem with inheritance: the whole ArrayList API leaks out
        System.out.println("\n=== The leaked API problem ===");
        bad.add("d");
        bad.set(0, "OVERWRITTEN");          // nobody counted this
        bad.removeIf(s -> s.equals("b"));   // nor this
        System.out.println("  after set() and removeIf(): " + bad);
        System.out.println("  getAddCount() = " + bad.getAddCount()
                           + " but size() = " + bad.size() + "  <-- inconsistent");
        System.out.println("\n  The composed version only exposes what we chose to expose,");
        System.out.println("  so its count can never drift out of sync.");
    }
}
Expected output
=== Inheritance version === added 3 items size() = 3 getAddCount() = 6 <-- WRONG === Composition version === added 3 items size() = 3 getAddCount() = 3 <-- CORRECT === The leaked API problem === after set() and removeIf(): [OVERWRITTEN, c, d] getAddCount() = 7 but size() = 3 <-- inconsistent The composed version only exposes what we chose to expose, so its count can never drift out of sync.
Why the inherited version says 6 addAll added 3 to the count, then called super.addAll(c) — and ArrayList.addAll internally calls add() for each element, which is your overridden add. So each item was counted twice. You depended on an internal implementation detail that ArrayList never promised, and which a future JDK could change. Composition has no such exposure: inner's internals can never call your methods.
The second, subtler problem Because InheritedCounter IS-A ArrayList, callers get set, removeIf, clear, sort — every method — and you cannot count or validate any of them. Inheritance forces you to inherit the entire public API, including the parts that break your invariants.
