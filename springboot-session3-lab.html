LAB 1▶ The Post Entity — a Class Becomes a Table
Concept An entity is a Java class that maps to a database table; each object is one row. You write the class, annotate it, and Hibernate generates the CREATE TABLE for you at startup. You will not write any SQL today.
⚠️ Import jakarta, never javax In Spring Boot 3.x the JPA package is jakarta.persistence. Older tutorials and Stack Overflow answers say javax.persistence — that was Boot 2.x and it will not compile. If your IDE offers both when auto-importing, always choose jakarta. This is the single most common error when copying older material.

  1. Right-click com.tcs.training.posts.entity → New → Class.
  2. Name it Post.
  3. Paste the whole file below.

package com.tcs.training.posts.entity;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity                       // "this class maps to a database table"
@Table(name = "posts")        // the table will be called 'posts'
public class Post {

    @Id                                                   // the PRIMARY KEY
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // the DB assigns it
    private Long id;          // Long (not long) so an unsaved Post can be null

    @Column(nullable = false, length = 200)               // NOT NULL, VARCHAR(200)
    private String title;

    @Column(nullable = false, length = 2000)
    private String content;

    @Column(nullable = false, length = 100)
    private String author;

    // ---- No-argument constructor: REQUIRED by JPA/Hibernate ----
    public Post() {
    }

    // ---- Convenience constructor (note: no id — the DB supplies it) ----
    public Post(String title, String content, String author) {
        this.title = title;
        this.content = content;
        this.author = author;
    }

    // ---- Getters and setters: needed by Hibernate AND by Jackson ----
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }

    public String getAuthor() {
        return author;
    }

    public void setAuthor(String author) {
        this.author = author;
    }
}

LAB 2▶ The Repository — Full CRUD From an Empty Interface
Concept — the shortest file you'll ever write Remember the twenty lines of JDBC in the theory deck, just to read one row? This is the replacement. You declare an interface with no methods, and at startup Spring Data generates the implementation and registers it as a bean. The two type parameters are <EntityType, PrimaryKeyType> — for us, <Post, Long>.

📄src/main/java/com/tcs/training/posts/repository/PostRepository.javacreate this — paste the WHOLE file
package com.tcs.training.posts.repository;

import com.tcs.training.posts.entity.Post;
import org.springframework.data.jpa.repository.JpaRepository;

import java.util.List;

// JpaRepository<Post, Long>  =  <the entity, the type of its @Id>
// Extending it gives us save, findAll, findById, deleteById, existsById,
// count, and paging/sorting — all without writing an implementation.
public interface PostRepository extends JpaRepository<Post, Long> {

    // ---- Derived queries: Spring Data writes the SQL from the METHOD NAME ----

    // SELECT * FROM posts WHERE author = ?
    List<Post> findByAuthor(String author);

    // SELECT * FROM posts WHERE lower(title) LIKE %?%
    List<Post> findByTitleContainingIgnoreCase(String keyword);

    // SELECT COUNT(*) FROM posts WHERE author = ?
    long countByAuthor(String author);
}
Expected result Compiles cleanly, and the app still starts. Nothing visible changes yet — nothing calls the repository until Lab 5.
Those three derived queries deserve a closer look You wrote no bodies, no SQL and no annotations. Spring Data reads each method name at startup, splits it into keywords, and generates the query:
  • findByAuthor → WHERE author = ?
  • findByTitleContainingIgnoreCase → WHERE lower(title) LIKE %?%
  • countByAuthor → SELECT COUNT(*) … WHERE author = ?
Try it — break it deliberately (30 seconds, very instructive) Rename findByAuthor to findByWriter and restart. The app refuses to start: 
org.springframework.data.repository.query.QueryCreationException:
Could not create query for public abstract java.util.List
  com.tcs.training.posts.repository.PostRepository.findByWriter(java.lang.String);
Reason: Failed to create query for method ...;
  No property 'writer' found for type 'Post'
Read the last line: "No property 'writer' found for type 'Post'". Spring Data checked your method name against the entity's fields and found no match. That's a good failure — caught at startup, not in production. Rename it back to findByAuthor.
LAB 3▶ The PostDTO — Your API's Public Shape
Concept — why a second class that looks almost the same? Our Post entity happens to hold nothing sensitive, so returning it directly would work. But consider a User entity with a passwordHash field: return that from a controller and Jackson publishes the hash to anyone who calls your API.

A DTO defines exactly what your API exposes — no more. It is safe by construction: when someone adds a sensitive field to the entity next year, it does not appear in the API, because the DTO doesn't mention it. We also hang our validation rules here, because this is the class that receives untrusted input.

  1. Right-click com.tcs.training.posts.dto → New → Class.

package com.tcs.training.posts.dto;

import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

// A plain data carrier. No @Entity — this class never touches the database.
// The validation annotations are enforced when the controller uses @Valid.
public class PostDTO {

    // Read-only from the client's point of view: we send it out, but the
    // database assigns it, so we never copy it back into an entity.
    private Long id;

    @NotBlank(message = "Title is required")
    @Size(min = 3, max = 200, message = "Title must be between 3 and 200 characters")
    private String title;

    @NotBlank(message = "Content is required")
    @Size(max = 2000, message = "Content cannot exceed 2000 characters")
    private String content;

    @NotBlank(message = "Author is required")
    private String author;

    // ---- No-arg constructor: required by Jackson to read incoming JSON ----
    public PostDTO() {
    }

    public PostDTO(Long id, String title, String content, String author) {
        this.id = id;
        this.title = title;
        this.content = content;
        this.author = author;
    }

    // ---- Getters and setters ----
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getTitle() {
        return title;
    }

    public void setTitle(String title) {
        this.title = title;
    }

    public String getContent() {
        return content;
    }

    public void setContent(String content) {
        this.content = content;
    }

    public String getAuthor() {
        return author;
    }

    public void setAuthor(String author) {
        this.author = author;
    }
}
Expected result Compiles cleanly. Note it has no JPA annotations at all — this class is never stored.
Entity vs DTO — the boundary rule
Post (entity)PostDTO

Entities never leave the service layer; DTOs never enter the repository layer. The service is the only place that imports both.
LAB 4▶ Exception Handling — Clean 404s Instead of Ugly 500s
Concept — two small classes that remove all your if checks In Session 2 every controller method carried an if (x == null) return notFound(). Today we replace all of it with two files:
  • PostNotFoundException — a custom exception meaning one specific thing. The service throws it and stops worrying.
  • GlobalExceptionHandler — one class annotated @RestControllerAdvice that catches exceptions from every controller and turns them into proper HTTP responses.
The pay-off: your controller ends up with zero error-handling code.
Do this — two files in the exception package
  1. Right-click com.tcs.training.posts.exception → New → Class → PostNotFoundException. Paste file 1.
  2. Same package → New → Class → GlobalExceptionHandler. Paste file 2.
📄src/main/java/com/tcs/training/posts/exception/PostNotFoundException.javafile 1 of 2 — paste the WHOLE file
package com.tcs.training.posts.exception;

// Extends RuntimeException (UNCHECKED), so we don't have to write
// "throws" on every method between the service and the handler.
public class PostNotFoundException extends RuntimeException {

    public PostNotFoundException(Long id) {
        // This message is what the client will eventually see.
        super("Post not found with id: " + id);
    }
}
📄src/main/java/com/tcs/training/posts/exception/GlobalExceptionHandler.javafile 2 of 2 — paste the WHOLE file
package com.tcs.training.posts.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.time.LocalDateTime;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;

// @RestControllerAdvice = "watch EVERY controller in this application".
// When one lets an exception escape, the matching method below handles it.
@RestControllerAdvice
public class GlobalExceptionHandler {

    // ---- 404: our custom exception ----
    @ExceptionHandler(PostNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handlePostNotFound(
            PostNotFoundException ex) {

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 404);
        body.put("error", "Not Found");
        body.put("message", ex.getMessage());

        return new ResponseEntity<>(body, HttpStatus.NOT_FOUND);
    }

    // ---- 400: @Valid failed on a @RequestBody ----
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> handleValidationErrors(
            MethodArgumentNotValidException ex) {

        // Collect every field error into a { fieldName: message } map
        Map<String, String> fieldErrors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(error ->
                fieldErrors.put(error.getField(), error.getDefaultMessage()));

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 400);
        body.put("error", "Validation Failed");
        body.put("fieldErrors", fieldErrors);

        return new ResponseEntity<>(body, HttpStatus.BAD_REQUEST);
    }

    // ---- 500: the safety net for anything we didn't anticipate ----
    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, Object>> handleEverythingElse(Exception ex) {

        // Log the FULL detail on the server, for us to debug...
        ex.printStackTrace();

        // ...but return only a generic message. Never leak a stack trace.
        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 500);
        body.put("error", "Internal Server Error");
        body.put("message", "An unexpected error occurred");

        return new ResponseEntity<>(body, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}
Expected result Both files compile, and the app still starts. You can't test them until the service throws — that's Lab 5, and you'll see the clean 404 in Lab 7.
The flow, end to end — worth tracing once in your head
  1. The client requests GET /api/posts/999.
  2. The controller calls postService.getPostById(999L).
  3. The service finds nothing and throws PostNotFoundException.
  4. The exception travels up past the controller, which does nothing about it.
  5. Spring finds the @ExceptionHandler(PostNotFoundException.class) method here.
  6. That method builds a 404 with a readable message and returns it.
The controller contains no error-handling code at all — the whole point of the exercise.
Why LinkedHashMap rather than HashMap for the body? Because LinkedHashMap preserves insertion order, so the JSON always comes out as timestamp, status, error, message — predictable and pleasant to read. A plain HashMap would order the keys arbitrarily. A small detail, but it's the kind of thing that makes an API feel considered.
LAB 5▶ The Service Layer — Interface + Implementation
Concept — where all the real work happens The service is the heart of the application, and it does three things:
  • Business logic — the rules, and coordinating the repository.
  • Entity ↔ DTO conversion — it is the only layer that knows both types.
  • Throwing exceptions — when something doesn't exist, it says so and stops.
We write it as an interface plus an implementation: the interface is the contract (what it can do) and the Impl class is the how. The controller will depend on the interface, so we could swap the implementation later without touching it. Note that @Service goes on the Impl — that's the class Spring instantiates.

import com.tcs.training.posts.dto.PostDTO;

import java.util.List;

// The CONTRACT: what the service can do. Notice every type here is a
// DTO — the entity is never mentioned, because callers must not see it.
public interface PostService {

    List<PostDTO> getAllPosts();

    PostDTO getPostById(Long id);

    PostDTO createPost(PostDTO postDTO);

    PostDTO updatePost(Long id, PostDTO postDTO);

📄src/main/java/com/tcs/training/posts/service/PostServiceImpl.javafile 2 of 2 — paste the WHOLE file
package com.tcs.training.posts.service;

import com.tcs.training.posts.dto.PostDTO;
import com.tcs.training.posts.entity.Post;
import com.tcs.training.posts.exception.PostNotFoundException;
import com.tcs.training.posts.repository.PostRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.ArrayList;
import java.util.List;

// @Service goes on the IMPLEMENTATION — this is the real bean.
@Service
public class PostServiceImpl implements PostService {

    private final PostRepository postRepository;

    // Constructor injection. Spring passes in the repository implementation
    // it generated for us at startup.
    public PostServiceImpl(PostRepository postRepository) {
        this.postRepository = postRepository;
    }

    // ================= READ ALL =================
    @Override
    @Transactional(readOnly = true)
    public List<PostDTO> getAllPosts() {
        List<PostDTO> result = new ArrayList<>();
        for (Post post : postRepository.findAll()) {
            result.add(toDTO(post));          // convert every entity to a DTO
        }
        return result;
    }

    // ================= READ ONE =================
    @Override
    @Transactional(readOnly = true)
    public PostDTO getPostById(Long id) {
        // THE key line of today's session: get it, or throw.
        // After this line 'post' is guaranteed non-null — no if needed.
        Post post = postRepository.findById(id)
                .orElseThrow(() -> new PostNotFoundException(id));
        return toDTO(post);
    }

    // ================= CREATE =================
    @Override
    @Transactional
    public PostDTO createPost(PostDTO postDTO) {
        Post saved = postRepository.save(toEntity(postDTO));
        // 'saved' now has the id the database assigned.
        return toDTO(saved);
    }

    // ================= UPDATE =================
    @Override
    @Transactional
    public PostDTO updatePost(Long id, PostDTO postDTO) {
        // 1. Load the existing row (or throw a clean 404)
        Post existing = postRepository.findById(id)
                .orElseThrow(() -> new PostNotFoundException(id));

        // 2. Change its fields — note we never touch the id
        existing.setTitle(postDTO.getTitle());
        existing.setContent(postDTO.getContent());
        existing.setAuthor(postDTO.getAuthor());

        // 3. save() issues an UPDATE, because the id is already set
        return toDTO(postRepository.save(existing));
    }

    // ================= DELETE =================
    @Override
    @Transactional
    public void deletePost(Long id) {
        // Check first, so a missing id gives a clean 404 rather than
        // an obscure framework exception.
        if (!postRepository.existsById(id)) {
            throw new PostNotFoundException(id);
        }
        postRepository.deleteById(id);
    }

    // ================= SEARCH =================
    @Override
    @Transactional(readOnly = true)
    public List<PostDTO> getPostsByAuthor(String author) {
        List<PostDTO> result = new ArrayList<>();
        for (Post post : postRepository.findByAuthor(author)) {
            result.add(toDTO(post));
        }
        return result;
    }

    // ============================================================
    //  MAPPING — the only place that knows about BOTH types
    // ============================================================

    // Entity -> DTO : going OUT to the client
    private PostDTO toDTO(Post post) {
        PostDTO dto = new PostDTO();
        dto.setId(post.getId());
        dto.setTitle(post.getTitle());
        dto.setContent(post.getContent());
        dto.setAuthor(post.getAuthor());
        return dto;
    }

    // DTO -> Entity : coming IN from the client
    private Post toEntity(PostDTO dto) {
        Post post = new Post();
        // We deliberately do NOT copy the id.
        // The DATABASE assigns ids — never the client.
        post.setTitle(dto.getTitle());
        post.setContent(dto.getContent());
        post.setAuthor(dto.getAuthor());
        return post;
    }
}
Expected result Both files compile and the app starts. One endpoint short of testable — the controller is next.
Three details in this file worth understanding, not just copying
  1. .orElseThrow(...) — this single line replaces every if (x == null) from Session 2. After it, the variable cannot be null, so the rest of the method reads as a clean happy path.
  2. toEntity never copies the id. If it did, a client could send "id": 7 in a POST and silently overwrite somebody else's row. The database owns ids.
  3. Update loads first, then modifies. We don't build a new Post — we fetch the existing row and change its fields, so save() issues an UPDATE rather than an INSERT.
What @Transactional is doing here Each write method is wrapped in a database transaction: if an exception escapes, everything it did is rolled back. The read methods use readOnly = true, which is a hint that lets Hibernate and the database optimise — it skips dirty-checking, since nothing can change.

package com.tcs.training.posts.controller;

import com.tcs.training.posts.dto.PostDTO;
import com.tcs.training.posts.service.PostService;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

import java.util.List;

@RestController
@RequestMapping("/api/posts")
public class PostController {

    // We depend on the INTERFACE, not PostServiceImpl.
    // Spring injects the implementation it found.
    private final PostService postService;

    public PostController(PostService postService) {
        this.postService = postService;
    }

    // GET /api/posts
    @GetMapping
    public ResponseEntity<List<PostDTO>> getAllPosts() {
        return ResponseEntity.ok(postService.getAllPosts());
    }

    // GET /api/posts/search?author=Amit
    // Declared before /{id} so the literal path is unambiguous.
    @GetMapping("/search")
    public ResponseEntity<List<PostDTO>> getByAuthor(@RequestParam String author) {
        return ResponseEntity.ok(postService.getPostsByAuthor(author));
    }

    // GET /api/posts/1
    // No null check! If it's missing, the service throws and the

BONUS 2▶ Make the Data Actually Survive a Restart
Concept Our H2 database is in memory, so restarting still wipes everything. H2 can also store to a file on disk — and switching over is a one-line change with zero Java modifications. That's the real lesson: the storage engine is configuration, not code.

The bigger point — this is how you'd move to MySQL You just changed where data lives without touching a single Java file. Going to MySQL in production is the same kind of change: swap the H2 dependency for the MySQL driver and edit four properties.

spring.datasource.driver-class-name=com.mysql.cj.jdbc.Driver
spring.datasource.username=root
spring.datasource.password=yourpassword
spring.jpa.database-platform=org.hibernate.dialect.MySQLDialect
spring.jpa.hibernate.ddl-auto=validate      # NEVER create/update in production
Your entity, repository, service and controller stay exactly as they are. That portability is what JPA bought you.

package com.tcs.training.posts.exception;

import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;

import java.time.LocalDateTime;
import java.util.HashMap;
import java.util.LinkedHashMap;
import java.util.Map;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(PostNotFoundException.class)
    public ResponseEntity<Map<String, Object>> handlePostNotFound(
            PostNotFoundException ex) {

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 404);
        body.put("error", "Not Found");
        body.put("message", ex.getMessage());

        return new ResponseEntity<>(body, HttpStatus.NOT_FOUND);
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<Map<String, Object>> handleValidationErrors(
            MethodArgumentNotValidException ex) {

        Map<String, String> fieldErrors = new HashMap<>();
        ex.getBindingResult().getFieldErrors().forEach(error ->
                fieldErrors.put(error.getField(), error.getDefaultMessage()));

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 400);
        body.put("error", "Validation Failed");
        body.put("fieldErrors", fieldErrors);

        return new ResponseEntity<>(body, HttpStatus.BAD_REQUEST);
    }

    @ExceptionHandler(Exception.class)
    public ResponseEntity<Map<String, Object>> handleEverythingElse(Exception ex) {

        ex.printStackTrace();

        Map<String, Object> body = new LinkedHashMap<>();
        body.put("timestamp", LocalDateTime.now());
        body.put("status", 500);
        body.put("error", "Internal Server Error");
        body.put("message", "An unexpected error occurred");

        return new ResponseEntity<>(body, HttpStatus.INTERNAL_SERVER_ERROR);
    }
}

📄service/PostServiceImpl.javafile 6b of 7 — implementation
package com.tcs.training.posts.service;

import com.tcs.training.posts.dto.PostDTO;
import com.tcs.training.posts.entity.Post;
import com.tcs.training.posts.exception.PostNotFoundException;
import com.tcs.training.posts.repository.PostRepository;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.util.ArrayList;
import java.util.List;

@Service
public class PostServiceImpl implements PostService {

    private final PostRepository postRepository;

    public PostServiceImpl(PostRepository postRepository) {
        this.postRepository = postRepository;
    }

    @Override
    @Transactional(readOnly = true)
    public List<PostDTO> getAllPosts() {
        List<PostDTO> result = new ArrayList<>();
        for (Post post : postRepository.findAll()) {
            result.add(toDTO(post));
        }
        return result;
    }

    @Override
    @Transactional(readOnly = true)
    public PostDTO getPostById(Long id) {
        Post post = postRepository.findById(id)
                .orElseThrow(() -> new PostNotFoundException(id));
        return toDTO(post);
    }

    @Override
    @Transactional
    public PostDTO createPost(PostDTO postDTO) {
        Post saved = postRepository.save(toEntity(postDTO));
        return toDTO(saved);
    }

    @Override
    @Transactional
    public PostDTO updatePost(Long id, PostDTO postDTO) {
        Post existing = postRepository.findById(id)
                .orElseThrow(() -> new PostNotFoundException(id));

        existing.setTitle(postDTO.getTitle());
        existing.setContent(postDTO.getContent());
        existing.setAuthor(postDTO.getAuthor());

        return toDTO(postRepository.save(existing));
    }

    @Override
    @Transactional
    public void deletePost(Long id) {
        if (!postRepository.existsById(id)) {
            throw new PostNotFoundException(id);
        }
        postRepository.deleteById(id);
    }

    @Override
    @Transactional(readOnly = true)
    public List<PostDTO> getPostsByAuthor(String author) {
        List<PostDTO> result = new ArrayList<>();
        for (Post post : postRepository.findByAuthor(author)) {
            result.add(toDTO(post));
        }
        return result;
    }

    private PostDTO toDTO(Post post) {
        PostDTO dto = new PostDTO();
        dto.setId(post.getId());
        dto.setTitle(post.getTitle());
        dto.setContent(post.getContent());
        dto.setAuthor(post.getAuthor());
        return dto;
    }

    private Post toEntity(PostDTO dto) {
        Post post = new Post();
        post.setTitle(dto.getTitle());
        post.setContent(dto.getContent());
        post.setAuthor(dto.getAuthor());
        return post;
    }
}

No property 'xyz' found for type 'Post' at startup A derived query method names a field the entity doesn't have. Match the entity field names exactly — findByAuthor, not findByWriter.
required a bean of type 'PostService' @Service missing from PostServiceImpl, or it's outside the base package. Put @Service on the Impl class (not the interface) and check its package.

500 instead of a clean 404 @RestControllerAdvice missing, or the handler class is outside the base package. Check the annotation and that the file is in com.tcs.training.posts.exception.
Validation never fires — bad data is accepted @Valid missing from the controller parameter, or no validation dependency. Add @Valid before @RequestBody, and confirm spring-boot-starter-validation is in pom.xml.

could not execute statement; NULL not allowed A @Column(nullable = false) field arrived empty. That's the database defending itself. Add validation so it's caught as a 400 first.
