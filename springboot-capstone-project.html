How this guide works

You've covered the building blocks in Sessions 1–4. This project puts them together in one realistic application and adds what real teams expect: validation, consistent errors, relationships, business rules, automated tests, role-based security, database migrations and API docs.

Every day has the same two parts
  • 🟢 Starter code: complete, working files for one feature. Copy them in, run the app, try the requests, and see the expected responses. Read every line; the comments explain the parts that are new.
  • 🏋️ Practice drills: 3–8 small tasks that use the same pattern on something else. Each drill says which part of the starter code to copy the pattern from, then gives a hint ladder: 💡 Hint 1 (a nudge), 🧭 Hint 2 (the shape of the code), ✅ Solution (the tested answer). Try first; open the solution to compare, or after 20 minutes stuck.

Tick each task as you finish it. Ticks and the "solutions opened" counter are saved in this browser, so you can close the page and continue tomorrow.

💻 What you need (nothing else to install)
  • JDK 17 or newer and IntelliJ IDEA or Eclipse, the same setup as the sessions.
  • A web browser. You'll send every request through Swagger UI, a test page that your own app serves at /swagger-ui.html. It's added as a normal Maven dependency on Day 0, so it needs no install and no admin rights. It replaces Postman and curl.
  • The H2 console (also served by your app) to look inside the database.
  • Your IDE's test runner (right-click → Run) for the automated tests from Day 5.
No Git? Your IDE keeps a Local History of every file, and on Day 0 you'll set up a simple zip checkpoint at the end of each day.
🤖 Using AI on this project, the right way
  • Ask for explanations and hints, not whole files. "Explain why…" and "What am I missing?" teach you. "Write my LoanService" doesn't.
  • State your versions in every prompt: "Spring Boot 4.1, Spring Framework 7, Spring Security 7, Hibernate 7, Java 17." AI tools often answer with Boot 2/3 code (javax.*, WebSecurityConfigurerAdapter, @MockBean, .and()), which won't compile here.
  • Don't paste code you can't explain line by line. Ask the AI to explain it first.
  • Trust the checks, not the chat. Code is done when the Swagger requests and (from Day 5) the tests give the expected results.

A library lends books to its members. Librarians manage the catalogue and handle returns. Members register themselves, browse the catalogue, borrow books and see their own loans. The API enforces the library's rules: loan limits, due dates and late fees.

package com.tcs.training.library.entity;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

@Entity
@Table(name = "books")
public class Book {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, unique = true, length = 13)
    private String isbn;

    @Column(nullable = false, length = 200)
    private String title;

    @Column(name = "published_year")
    private Integer publishedYear;

    @Column(name = "total_copies", nullable = false)
    private int totalCopies;

    @Column(name = "available_copies", nullable = false)
    private int availableCopies;

    protected Book() {
        // required by JPA
    }

    public Book(String isbn, String title, Integer publishedYear, int totalCopies) {
        this.isbn = isbn;
        this.title = title;
        this.publishedYear = publishedYear;
        this.totalCopies = totalCopies;
        this.availableCopies = totalCopies;   // a new book starts with every copy on the shelf
    }

    /** Day 1 version: nobody can borrow yet, so every copy is on the shelf. Day 4 makes this smarter. */
    public void changeTotalCopies(int newTotal) {
        this.totalCopies = newTotal;
        this.availableCopies = newTotal;
    }

    public Long getId() { return id; }
    public String getIsbn() { return isbn; }
    public void setIsbn(String isbn) { this.isbn = isbn; }
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    public Integer getPublishedYear() { return publishedYear; }
    public void setPublishedYear(Integer publishedYear) { this.publishedYear = publishedYear; }
    public int getTotalCopies() { return totalCopies; }
    public int getAvailableCopies() { return availableCopies; }
}
Why no setter for availableCopies? If any code could call setAvailableCopies(-5), nothing would protect the numbers. Changes go through methods on Book instead, so there's one place to enforce the rules. Day 4 relies on this.

📄src/main/java/com/tcs/training/library/service/BookService.javanew file
package com.tcs.training.library.service;

import com.tcs.training.library.dto.BookRequest;
import com.tcs.training.library.dto.BookResponse;
import com.tcs.training.library.entity.Book;
import com.tcs.training.library.exception.ResourceNotFoundException;
import com.tcs.training.library.repository.BookRepository;
import java.util.List;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@Transactional(readOnly = true)
public class BookService {

    private final BookRepository bookRepository;

    public BookService(BookRepository bookRepository) {   // constructor injection: no @Autowired needed
        this.bookRepository = bookRepository;
    }

    @Transactional
    public BookResponse create(BookRequest request) {
        Book book = new Book(request.isbn(), request.title(), request.publishedYear(), request.totalCopies());
        return BookResponse.from(bookRepository.save(book));
    }

    public List<BookResponse> findAll() {
        return bookRepository.findAll().stream()
                .map(BookResponse::from)
                .toList();
    }

    public BookResponse findById(Long id) {
        return BookResponse.from(getBook(id));
    }

    @Transactional
    public BookResponse update(Long id, BookRequest request) {
        Book book = getBook(id);
        book.setIsbn(request.isbn());
        book.setTitle(request.title());
        book.setPublishedYear(request.publishedYear());
        book.changeTotalCopies(request.totalCopies());
        return BookResponse.from(book);   // no save() needed: the entity is managed, changes flush on commit
    }

    @Transactional
    public void delete(Long id) {
        bookRepository.delete(getBook(id));
    }

    private Book getBook(Long id) {
        return bookRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Book", id));
    }
}
Two ideas in this service
  • Constructor injection. The dependency is private final and arrives through the constructor. With one constructor Spring injects it automatically, no @Autowired needed, and tests can simply call new BookService(fakeRepository).
  • Transactions and dirty checking. @Transactional(readOnly = true) on the class makes every method a read-only transaction; write methods override it with plain @Transactional. Inside a transaction a loaded entity is managed: change its fields and Hibernate writes the change on commit. That's why update never calls save().

package com.tcs.training.library.controller;

import com.tcs.training.library.dto.BookRequest;
import com.tcs.training.library.dto.BookResponse;
import com.tcs.training.library.service.BookService;
import java.net.URI;
import java.util.List;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.PutMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/books")
public class BookController {

    private final BookService bookService;

    public BookController(BookService bookService) {
        this.bookService = bookService;
    }

    @PostMapping
    public ResponseEntity<BookResponse> create(@RequestBody BookRequest request) {
        BookResponse created = bookService.create(request);
        return ResponseEntity.created(URI.create("/api/books/" + created.id())).body(created);
    }

    @GetMapping
    public List<BookResponse> findAll() {
        return bookService.findAll();
    }

    @GetMapping("/{id}")
    public BookResponse findById(@PathVariable Long id) {
        return bookService.findById(id);
    }

    @PutMapping("/{id}")
    public BookResponse update(@PathVariable Long id, @RequestBody BookRequest request) {
        return bookService.update(id, request);
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> delete(@PathVariable Long id) {
        bookService.delete(id);
        return ResponseEntity.noContent().build();
    }
}

Check yourself

Why return a DTO instead of the Book entity?
The entity is your database schema. Returning it ties your public API to the table: rename a column and clients break. It can also leak fields (from Day 6, a password hash), cause infinite JSON loops with relationships, and trigger lazy-loading errors. A DTO is a separate contract you control.
Why 201 + Location for POST and 204 for DELETE?
HTTP defines 201 Created for "a new resource exists now", and Location tells the client its URL. 204 No Content means "done, nothing to send back". Using the right codes lets clients and tools behave correctly without reading the body.
How did findByIsbn work with no code?
Spring Data parses the method name: findBy + property Isbn becomes select b from Book b where b.isbn = ?1. You'll use this "derived query" style a lot on Days 2–4.

import java.util.Map;
import org.springframework.dao.DataIntegrityViolationException;
import org.springframework.http.HttpHeaders;
import org.springframework.http.HttpStatus;
import org.springframework.http.HttpStatusCode;
import org.springframework.http.ProblemDetail;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import org.springframework.web.context.request.WebRequest;
import org.springframework.web.servlet.mvc.method.annotation.ResponseEntityExceptionHandler;

@RestControllerAdvice
public class GlobalExceptionHandler extends ResponseEntityExceptionHandler {

    @ExceptionHandler(ResourceNotFoundException.class)
    public ProblemDetail handleNotFound(ResourceNotFoundException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.NOT_FOUND, ex.getMessage());
        problem.setTitle("Resource not found");
        return problem;
    }

    @ExceptionHandler(BusinessRuleException.class)
    public ProblemDetail handleBusinessRule(BusinessRuleException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT, ex.getMessage());
        problem.setTitle("Business rule violated");
        return problem;
    }

    @ExceptionHandler(DataIntegrityViolationException.class)
    public ProblemDetail handleDataIntegrity(DataIntegrityViolationException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.CONFLICT,
                "The request conflicts with existing data (for example a duplicate value)");
        problem.setTitle("Data conflict");
        return problem;
    }


    @ExceptionHandler(BadRequestException.class)
    public ProblemDetail handleBadRequest(BadRequestException ex) {
        ProblemDetail problem = ProblemDetail.forStatusAndDetail(HttpStatus.BAD_REQUEST, ex.getMessage());
        problem.setTitle("Bad request");
        return problem;
    }

    @Override
    protected ResponseEntity<Object> handleMethodArgumentNotValid(MethodArgumentNotValidException ex,
            HttpHeaders headers, HttpStatusCode status, WebRequest request) {
        Map<String, String> errors = new LinkedHashMap<>();
        ex.getBindingResult().getFieldErrors()
                .forEach(error -> errors.putIfAbsent(error.getField(), error.getDefaultMessage()));

        ProblemDetail problem = ex.getBody();
        problem.setTitle("Validation failed");
        problem.setDetail("One or more fields are invalid");
        problem.setProperty("errors", errors);
        return handleExceptionInternal(ex, problem, headers, status, request);
    }
}
How the handler works @RestControllerAdvice catches exceptions thrown from any controller. Each @ExceptionHandler method turns one exception type into a ProblemDetail; Spring fills in status and instance (the path). Extending ResponseEntityExceptionHandler also covers Spring's own errors (malformed JSON, /api/books/abc), and the override adds an errors map of field → message for validation failures. ResourceNotFoundException no longer needs @ResponseStatus.

import com.tcs.training.library.dto.BookRequest;
import com.tcs.training.library.dto.BookResponse;
import com.tcs.training.library.dto.PageResponse;
import com.tcs.training.library.entity.Book;
import com.tcs.training.library.exception.BadRequestException;
import com.tcs.training.library.exception.BusinessRuleException;
import com.tcs.training.library.exception.ResourceNotFoundException;
import com.tcs.training.library.repository.BookRepository;
import java.util.List;
import org.springframework.data.domain.Pageable;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@Transactional(readOnly = true)
public class BookService {

    private static final List<String> SORTABLE_FIELDS = List.of("title", "publishedYear", "availableCopies");

    private final BookRepository bookRepository;

    public BookService(BookRepository bookRepository) {
        this.bookRepository = bookRepository;
    }

    @Transactional
    public BookResponse create(BookRequest request) {
        if (bookRepository.existsByIsbn(request.isbn())) {
            throw new BusinessRuleException("A book with ISBN " + request.isbn() + " already exists");
        }
        Book book = new Book(request.isbn(), request.title().trim(), request.publishedYear(), request.totalCopies());
        return BookResponse.from(bookRepository.save(book));
    }

    public PageResponse<BookResponse> search(String title, boolean availableOnly, Pageable pageable) {
        pageable.getSort().forEach(order -> {
            if (!SORTABLE_FIELDS.contains(order.getProperty())) {
                throw new BadRequestException(
                        "Cannot sort by '" + order.getProperty() + "'. Allowed: " + SORTABLE_FIELDS);
            }
        });
        String titleFilter = (title == null) ? "" : title.trim();
        return PageResponse.from(
                bookRepository.search(titleFilter, availableOnly, pageable).map(BookResponse::from));
    }

    public BookResponse findById(Long id) {
        return BookResponse.from(getBook(id));
    }

    public BookResponse findByIsbn(String isbn) {
        return bookRepository.findByIsbn(isbn)
                .map(BookResponse::from)
                .orElseThrow(() -> new ResourceNotFoundException("Book with ISBN " + isbn + " was not found"));
    }

    @Transactional
    public BookResponse update(Long id, BookRequest request) {
        Book book = getBook(id);
        if (bookRepository.existsByIsbnAndIdNot(request.isbn(), id)) {
            throw new BusinessRuleException("A book with ISBN " + request.isbn() + " already exists");
        }
        book.setIsbn(request.isbn());
        book.setTitle(request.title().trim());
        book.setPublishedYear(request.publishedYear());
        book.changeTotalCopies(request.totalCopies());
        return BookResponse.from(book);
    }

    @Transactional
    public void delete(Long id) {
        bookRepository.delete(getBook(id));
    }

    private Book getBook(Long id) {
        return bookRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Book", id));
    }
}
Three new ideas
  • Check, then throw 409. existsByIsbn catches duplicates with a friendly message before the database constraint does. The DataIntegrityViolationException handler still returns 409 if two requests race past the check at the same moment.
  • One query, optional filters. An empty title matches everything (like '%%'), and :availableOnly = false or … switches the second filter off.
  • Whitelist sort fields. Without it, ?sort=nonsense crashes deep inside Spring Data with a 500.

400 or 409: how do you choose?
400: the request itself is invalid, which you can tell without the database (blank title, 3-digit ISBN). 409: the request is well-formed but conflicts with current data (ISBN taken, no copies left). The same 409 request might succeed later; the same 400 request never will.
When @Query, when a derived query?
Derived queries are great for one or two simple conditions (findByNameContainingIgnoreCase). Once the name gets long or you need optional filters like :authorId is null or …, write JPQL with @Query; it's easier to read.

                throw new BadRequestException(
                        "Cannot sort by '" + order.getProperty() + "'. Allowed: " + SORTABLE_FIELDS);
            }

                authorRepository.findByNameContainingIgnoreCase(nameFilter, pageable).map(AuthorResponse::from));

    private Long id;

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "book_id", nullable = false)

        return returnedOn == null;

Check yourself

Why are R3 and R8 in Book, but R2, R4 and R5 in LoanService?
R3 and R8 only need the book's own fields, so the book protects itself. R2, R4 and R5 need other data (the member's other loans), which an entity can't query, so they belong in the service.
Why BigDecimal for the fee?
double is binary floating point: 0.1 + 0.2 is 0.30000000000000004. Money drifts over many transactions. BigDecimal stores exact decimals, and the column is NUMERIC(10,2) to match.
What is a lost update, and how does @Version stop it?
Two transactions read availableCopies = 1, both subtract one, both write 0, and two loans exist for one copy. With @Version, each update says "only if version is still 5". The first sets it to 6; the second updates 0 rows, and Hibernate throws instead of overwriting.

import org.springframework.beans.factory.annotation.Autowired;

import org.springframework.boot.webmvc.test.autoconfigure.AutoConfigureMockMvc;

@Transactional   // each test rolls back, so tests do not see each other's data
class LoanFlowIntegrationTest {

    @Autowired MockMvc mockMvc;

    @Test
    void borrowingTheLastCopyMakesTheBookUnavailable() throws Exception {
        Number authorId = createAndReadId("/api/authors", """
                {"name":"Robert C. Martin"}
                """);
        Number bookId = createAndReadId("/api/books", """
                {"isbn":"9780132350884","title":"Clean Code","totalCopies":1,"authorId":%d}

                {"name":"Ravi","email":"ravi@example.com"}
                """);

                {"bookId":%d,"memberId":%d}

                .andExpect(status().isCreated())
                .andExpect(jsonPath("$.status").value("ACTIVE"));

                .andExpect(jsonPath("$.availableCopies").value(0));

                {"name":"Meera","email":"meera@example.com"}
                """);

                {"bookId":%d,"memberId":%d}
                """.formatted(bookId.longValue(), secondMemberId.longValue());
        mockMvc.perform(post("/api/loans").contentType(MediaType.APPLICATION_JSON).content(secondBorrow))

                .andExpect(status().isCreated())
                .andReturn().getResponse().getContentAsString();

Why does the unit test use new LoanService(…) instead of letting Spring create it?
No Spring context means the test runs in milliseconds and tests only the service's logic. Constructor injection is what makes it possible; with @Autowired fields you'd need Spring or reflection to supply the dependencies.
What should you mock, and what not?
Mock collaborators that do I/O or are expensive: repositories, other services, clocks (or use a fixed one). Use real objects for simple values and entities with logic, like Book; mocking them would replace the very logic you want to check.

import com.tcs.training.library.dto.MemberRequest;

import com.tcs.training.library.entity.Member;
import com.tcs.training.library.entity.Role;
import com.tcs.training.library.exception.BusinessRuleException;
import com.tcs.training.library.exception.ResourceNotFoundException;
import com.tcs.training.library.repository.MemberRepository;
import java.time.Clock;
import java.time.LocalDate;
import java.util.List;
import org.springframework.data.domain.Sort;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@Transactional(readOnly = true)
public class MemberService {

    private final MemberRepository memberRepository;
    private final PasswordEncoder passwordEncoder;
    private final Clock clock;

    public MemberService(MemberRepository memberRepository, PasswordEncoder passwordEncoder, Clock clock) {
        this.memberRepository = memberRepository;
        this.passwordEncoder = passwordEncoder;
        this.clock = clock;
    }

    @Transactional
    public MemberResponse register(MemberRequest request) {
        String email = request.email().trim().toLowerCase();
        if (memberRepository.existsByEmailIgnoreCase(email)) {
            throw new BusinessRuleException("A member with email " + email + " already exists");
        }
        Member member = new Member(request.name().trim(), email, LocalDate.now(clock),
                passwordEncoder.encode(request.password()), Role.MEMBER);
        return MemberResponse.from(memberRepository.save(member));
    }

    public List<MemberResponse> findAll() {
        return memberRepository.findAll(Sort.by("name")).stream()
                .map(MemberResponse::from)
                .toList();
    }

    public MemberResponse findById(Long id) {
        return MemberResponse.from(getMember(id));
    }

    Member getMember(Long id) {
        return memberRepository.findById(id)
                .orElseThrow(() -> new ResourceNotFoundException("Member", id));
    }

    Member getMemberByEmail(String email) {
        return memberRepository.findByEmailIgnoreCase(email)
                .orElseThrow(() -> new ResourceNotFoundException("No member with email " + email));
    }
}
Details that matter
  • Never store a password, only its BCrypt hash. The response DTO has no password field at all, so it can't leak.
  • Max 72 characters: BCrypt only uses the first 72 bytes.
  • EnumType.STRING: the default, ORDINAL, stores 0 and 1. Insert a new role at the top of the enum later and every user's role silently changes.

package com.tcs.training.library.security;

import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;
import java.io.IOException;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpMethod;
import org.springframework.http.HttpStatus;
import org.springframework.security.access.AccessDeniedException;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.core.AuthenticationException;
import org.springframework.security.crypto.bcrypt.BCryptPasswordEncoder;
import org.springframework.security.crypto.password.PasswordEncoder;
import org.springframework.security.web.SecurityFilterChain;

@Configuration
public class SecurityConfig {

    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            .csrf(AbstractHttpConfigurer::disable)   // stateless REST API: no browser session, no CSRF cookie
            .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
            .headers(headers -> headers.frameOptions(frame -> frame.sameOrigin()))   // H2 console uses frames
            .authorizeHttpRequests(auth -> auth
                // public
                .requestMatchers("/h2-console/**").permitAll()   // dev only: the console has its own login
                .requestMatchers(HttpMethod.POST, "/api/members").permitAll()
                .requestMatchers("/actuator/health", "/actuator/info").permitAll()
                .requestMatchers("/swagger-ui.html", "/swagger-ui/**", "/v3/api-docs/**").permitAll()
                // any logged-in user can browse the catalogue
                .requestMatchers(HttpMethod.GET, "/api/books/**", "/api/authors/**").hasAnyRole("MEMBER", "LIBRARIAN")
                // members manage their own loans
                .requestMatchers("/api/me/**").hasRole("MEMBER")
                // everything else under /api is staff only
                .requestMatchers("/api/**").hasRole("LIBRARIAN")
                .anyRequest().authenticated())
            // HTTP Basic login, but answer 401/403 with JSON instead of making the browser pop up its own login box
            .httpBasic(basic -> basic.authenticationEntryPoint(this::notLoggedIn))
            .exceptionHandling(ex -> ex
                .authenticationEntryPoint(this::notLoggedIn)
                .accessDeniedHandler(this::notAllowed));
        return http.build();
    }

    @Bean
    public PasswordEncoder passwordEncoder() {
        return new BCryptPasswordEncoder();
    }

    private void notLoggedIn(HttpServletRequest request, HttpServletResponse response,
                             AuthenticationException ex) throws IOException {
        writeProblem(response, HttpStatus.UNAUTHORIZED, "Log in with your email and password");
    }

    private void notAllowed(HttpServletRequest request, HttpServletResponse response,
                            AccessDeniedException ex) throws IOException {
        writeProblem(response, HttpStatus.FORBIDDEN, "Your role is not allowed to do this");
    }

    /** Same shape as the ProblemDetail errors from GlobalExceptionHandler. */
    private void writeProblem(HttpServletResponse response, HttpStatus status, String detail) throws IOException {
        response.setStatus(status.value());
        response.setContentType("application/problem+json");
        response.getWriter().write("{\"title\":\"" + status.getReasonPhrase() + "\",\"status\":" + status.value()
                + ",\"detail\":\"" + detail + "\"}");
    }
}
Reading SecurityConfig
  • Rules are checked top to bottom; the first match wins. Specific rules first, the broad "/api/**" last. hasRole("LIBRARIAN") checks for the authority ROLE_LIBRARIAN; the prefix is added for you.
  • CSRF off, stateless: CSRF attacks abuse a session cookie the browser sends automatically. This API has no session cookie (credentials go with every request), so there's nothing to protect. A browser app with session login keeps CSRF on.
  • The two small methods at the bottom answer 401/403 with JSON. Without them, Spring sends a header that makes the browser pop up its own login box over Swagger UI.
  • This is Spring Security 7 lambda style. If an AI suggests WebSecurityConfigurerAdapter or .and(), its answer is out of date.

    }

package com.tcs.training.library.service;

import com.tcs.training.library.config.LoanProperties;
import com.tcs.training.library.dto.LoanResponse;
import com.tcs.training.library.entity.Book;
import com.tcs.training.library.entity.Loan;
import com.tcs.training.library.entity.Member;
import com.tcs.training.library.exception.BusinessRuleException;
import com.tcs.training.library.exception.ResourceNotFoundException;
import com.tcs.training.library.repository.LoanRepository;
import java.math.BigDecimal;
import java.time.Clock;
import java.time.LocalDate;
import java.time.temporal.ChronoUnit;
import java.util.List;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
@Transactional(readOnly = true)
public class LoanService {

    private final LoanRepository loanRepository;
    private final BookService bookService;
    private final MemberService memberService;
    private final LoanProperties rules;
    private final Clock clock;

    public LoanService(LoanRepository loanRepository, BookService bookService, MemberService memberService,
                       LoanProperties rules, Clock clock) {
        this.loanRepository = loanRepository;
        this.bookService = bookService;
        this.memberService = memberService;
        this.rules = rules;
        this.clock = clock;
    }

    @Transactional
    public LoanResponse borrow(Long bookId, Long memberId) {
        Member member = memberService.getMember(memberId);   // 404 if missing
        return borrow(bookService.getBook(bookId), member);
    }

    /** Drill 6.C: a member borrows for themselves; the email comes from their login. */
    @Transactional
    public LoanResponse borrowForMember(String email, Long bookId) {
        Member member = memberService.getMemberByEmail(email);
        return borrow(bookService.getBook(bookId), member);
    }

    /** The rules, shared by both ways of borrowing. Called only from @Transactional methods above. */
    private LoanResponse borrow(Book book, Member member) {
        LocalDate today = LocalDate.now(clock);

        // R5 (drill 4.F): no new loans while one is overdue
        if (loanRepository.existsByMemberIdAndReturnedOnIsNullAndDueOnBefore(member.getId(), today)) {
            throw new BusinessRuleException("Member has an overdue loan. Return it before borrowing again");
        }
        // R2 (drill 4.B): at most maxActiveLoans at once
        if (loanRepository.countByMemberIdAndReturnedOnIsNull(member.getId()) >= rules.maxActiveLoans()) {
            throw new BusinessRuleException("Member already has " + rules.maxActiveLoans() + " active loans");
        }
        // R4 (drill 4.A): not two copies of the same book
        if (loanRepository.existsByMemberIdAndBookIdAndReturnedOnIsNull(member.getId(), book.getId())) {
            throw new BusinessRuleException("Member already has a copy of '" + book.getTitle() + "'");
        }

        book.borrowCopy();                                   // R3: throws if no copies are left
        Loan loan = new Loan(book, member, today, today.plusDays(rules.loanDays()));   // R1
        return LoanResponse.from(loanRepository.save(loan), today);
    }

    /** Drill 4.D: return a loan and charge any late fee (R6). */
    @Transactional
    public LoanResponse returnLoan(Long loanId) {
        Loan loan = loanRepository.findById(loanId)
                .orElseThrow(() -> new ResourceNotFoundException("Loan", loanId));
        if (!loan.isActive()) {
            throw new BusinessRuleException("Loan " + loanId + " was already returned on " + loan.getReturnedOn());
        }

        LocalDate today = LocalDate.now(clock);
        long daysLate = Math.max(0, ChronoUnit.DAYS.between(loan.getDueOn(), today));
        BigDecimal fee = rules.feePerDay().multiply(BigDecimal.valueOf(daysLate));

        loan.markReturned(today, fee);
        loan.getBook().returnCopy();
        return LoanResponse.from(loan, today);
    }

    /** Drill 4.C: a member's loans, newest first. */
    public List<LoanResponse> findByMember(Long memberId) {
        memberService.getMember(memberId);   // 404 if the member does not exist
        return toResponses(loanRepository.findByMemberIdOrderByBorrowedOnDesc(memberId));
    }

    /** Drill 6.B */
    public List<LoanResponse> findByMemberEmail(String email) {
        Member member = memberService.getMemberByEmail(email);
        return toResponses(loanRepository.findByMemberIdOrderByBorrowedOnDesc(member.getId()));
    }

    /** Drill 4.E: every active loan whose due date has passed. */
    public List<LoanResponse> findOverdue() {
        LocalDate today = LocalDate.now(clock);
        return toResponses(loanRepository.findByReturnedOnIsNullAndDueOnBeforeOrderByDueOn(today));
    }

    private List<LoanResponse> toResponses(List<Loan> loans) {
        LocalDate today = LocalDate.now(clock);
        return loans.stream().map(loan -> LoanResponse.from(loan, today)).toList();
    }
}

Check yourself

Authentication vs authorisation, 401 vs 403?
Authentication: "who are you?" Failing it gives 401 (the name is historical; it means "unauthenticated"). Authorisation: "are you allowed to do this?" Failing it gives 403. Asha with a wrong password: 401. Asha adding a book: 403.
Why BCrypt instead of SHA-256?
SHA-256 is designed to be fast, so a thief with your database can try billions of guesses per second. BCrypt is deliberately slow (adjustable cost) and adds a random salt per hash, so identical passwords get different hashes and precomputed tables don't help.
Is HTTP Basic safe?
Only over HTTPS. It sends the email and password, base64-encoded (not encrypted), on every request. Fine for an internal API behind TLS; public APIs usually swap the password for a short-lived token (the JWT stretch).

💡 Hint 1
The error in step 1 is Schema validation: missing column [phone] in table [members]: validate caught the code and the database disagreeing. The SQL is one line: ALTER TABLE members ADD COLUMN …. In a Java string the regex needs double backslashes: "\\+?[0-9 ]{7,20}". @Pattern ignores null, so the field stays optional.
🧭 Hint 2: why a setter, not a constructor argument?
Adding a constructor parameter would break every new Member(…) call, including LoanServiceTest and LibrarianSeeder. An optional field with a setter keeps those working. Ask yourself this whenever you add a field.

Check yourself

Why validate instead of update in production?
update lets Hibernate alter tables based on your entities, with no review, no history and no rollback plan, and it can't rename or drop columns safely. validate changes nothing; it fails fast when the reviewed migrations and the code disagree, exactly as you saw in 7.B.
Why not expose all Actuator endpoints?
env, configprops, heapdump and loggers can reveal configuration and secrets, or change behaviour at runtime. Expose the minimum publicly; put anything else behind a role or a separate management port.
