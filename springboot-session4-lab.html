⚠️ The Golden Rule, four times over

Each project has its own base package, and each one is derived by Spring Initializr from Group + Artifact with the hyphen removed. Every class you create must sit in that package or below it.

Artifact eureka-server→ base package com.tcs.training.eurekaserver
Artifact student-ms→ base package com.tcs.training.studentms
Artifact customer-ms→ base package com.tcs.training.customerms
Artifact api-gateway→ base package com.tcs.training.apigateway

Notice the hyphen disappears: student-ms becomes studentms, because a Java package name can't contain a hyphen. Initializr strips it automatically. In every project, open the main class and read its package line before you write anything — that's your five-second check, and it's the difference between a working lab and an afternoon of silent 404s.

package com.tcs.training.studentms.controller;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/api/students")
public class StudentController {

    // @Value injects a property at startup. We inject our OWN port so every
    // response can announce which instance answered — that is how you will
    // SEE load balancing working in Lab 7.
    @Value("${server.port}")
    private String port;

    // GET /api/students
    @GetMapping
    public Map<String, Object> getAllStudents() {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("service", "STUDENT-MS");
        response.put("servedByPort", port);          // ← watch this value change
        response.put("students", List.of("Amit Shah", "Neha Patel", "Ravi Kumar"));
        return response;
    }

    // GET /api/students/1
    @GetMapping("/{id}")
    public Map<String, Object> getStudentById(@PathVariable int id) {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("service", "STUDENT-MS");
        response.put("servedByPort", port);
        response.put("id", id);
        response.put("name", "Student number " + id);
        return response;
    }
}

LAB 4:8082:8083▶ Scale Student MS to Three Instances
Concept — horizontal scaling, for real This is horizontal scaling from the theory deck: instead of one bigger machine, run more copies of the same application. Same code, same JAR, different port. Each copy registers itself under the same name STUDENT-MS, so Eureka ends up listing one service with three instances — and any caller asking for STUDENT-MS gets all three back.

This only works because the service is stateless (Session 2). If it kept per-user data in memory, three copies would disagree with each other.
Do this — pick whichever method suits your setup

Do NOT edit application.properties. We override the port at launch time, so all three instances run the identical build.

  1. Method A — terminal (simplest). Open two new terminal tabs in the student-ms folder and run one command in each.
  2. Method B — IntelliJ. Run → Edit Configurations → select StudentMsApplication → click Copy Configuration (the duplicate icon) → name it StudentMs-8082 → in Program arguments put --server.port=8082. Repeat for 8083. Then run both. (If you don't see "Program arguments", enable Modify options → Program arguments.)
  3. Method C — Eclipse. Run → Run Configurations → select the app → duplicate it → Arguments tab → Program arguments: --server.port=8082. Repeat for 8083.

"Netty started" — why not Tomcat? Spring Cloud Gateway runs on Netty, a non-blocking server, because a gateway spends almost all its time waiting on other services. A blocking server would tie up one thread per waiting request; Netty handles thousands of concurrent waits on a handful of threads. That's also exactly why adding Spring Web here breaks things — it would try to start Tomcat instead.

🚨 Getting 404 through the gateway when direct calls work?
  1. Wrong property prefix. By far the most likely cause — see the version box in Lab 5. Try the other form.
  2. Wrong service name. The name in lb://STUDENT-MS must match the Eureka dashboard exactly, upper-case.
  3. Gateway not registered. Check API-GATEWAY appears in Eureka — without that it can't resolve lb:// names.
  4. Path predicate typo. Path=/api/students/** — the ** is required to match sub-paths.
  5. Spring Web on the classpath. Check pom.xml and remove spring-boot-starter-web if it's there.
Inspect the gateway's own routes Add these two lines to the gateway's properties, restart, then open http://localhost:9393/actuator/gateway/routes: 
management.endpoints.web.exposure.include=health,info,gateway
management.endpoint.gateway.access=unrestricted
You get JSON listing every route the gateway actually loaded. If your route isn't in that list, it was never parsed — which points straight back at the property prefix. (On older Spring Boot versions the second property is management.endpoint.gateway.enabled=true.)

  • Horizontal scaling — three copies of one stateless service.
  • Load balancing — requests distributed round-robin, visibly.
  • High availability — an instance died and the service kept serving.
  • Self-healing — it rejoined by itself with zero configuration.
This is the core of every large-scale system you use daily. You built it in one session.

Concept — the automatic alternative In Lab 5 you wrote a route block per service. That's explicit and controllable, but every new service means new config. Discovery locator is the other approach: switch it on and every service registered in Eureka becomes routable immediately at /{service-name}/**. Zero config per service.
Do this — swap the gateway config
  1. In the gateway's application.properties, comment out both routes[...] blocks (put # in front of each line).
  2. Add the two discovery-locator lines below — matching your Spring Cloud version.
  3. Restart only the gateway. Leave everything else running.
  4. Test the new URL shape.

Which approach should you actually use?
Manual routesDiscovery locator

Clean public URLsYes — you choose themService name leaks into the path

Discovery locator is excellent for local development and for seeing the registry in action — which is exactly what we used it for.

A 200 means "yes, I still have you on the list." Stop sending these for ~90 seconds and Eureka evicts the instance — which is precisely what you triggered by killing an instance in Lab 7.
Part 2 — read the registry as data

The dashboard is just a web page over an API. Query it yourself:

Faster eviction, for impatient experiments 90 seconds is a long wait during a lab. On the Eureka server, these settings make failures visible much sooner: 
# Eureka server — DEVELOPMENT ONLY
eureka.server.enable-self-preservation=false
eureka.server.eviction-interval-timer-in-ms=5000
And on a client, to heartbeat more often: 
eureka.instance.lease-renewal-interval-in-seconds=5
eureka.instance.lease-expiration-duration-in-seconds=10
Never do this in production. Self-preservation exists to stop Eureka de-registering healthy services during a brief network blip — turning it off makes a momentary glitch look like a mass outage.

Concept So far the gateway resolves service names. But services often need to call each other directly. Here Customer MS will fetch data from Student MS by name, with no address anywhere — and it gets load balancing across all three instances for free.

📄customer-ms/src/main/java/com/tcs/training/customerms/config/AppConfig.javafile 1 of 2 — create this
package com.tcs.training.customerms.config;

import org.springframework.cloud.client.loadbalancer.LoadBalanced;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.web.client.RestTemplate;

@Configuration
public class AppConfig {

    // @LoadBalanced is the whole trick. It teaches this RestTemplate to
    // treat the "host" in a URL as a EUREKA SERVICE NAME, look it up in the
    // registry, and round-robin across the instances it finds.
    @Bean
    @LoadBalanced
    public RestTemplate restTemplate() {
        return new RestTemplate();
    }
}
📄customer-ms/src/main/java/com/tcs/training/customerms/controller/CustomerController.javafile 2 of 2 — replace the whole file
package com.tcs.training.customerms.controller;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.client.RestTemplate;

import java.util.LinkedHashMap;
import java.util.List;
import java.util.Map;

@RestController
@RequestMapping("/api/customers")
public class CustomerController {

    @Value("${server.port}")
    private String port;

    private final RestTemplate restTemplate;

    // The @LoadBalanced RestTemplate bean from AppConfig is injected here.
    public CustomerController(RestTemplate restTemplate) {
        this.restTemplate = restTemplate;
    }

    @GetMapping
    public Map<String, Object> getAllCustomers() {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("service", "CUSTOMER-MS");
        response.put("servedByPort", port);
        response.put("customers", List.of("Tata Motors", "Infosys", "Reliance"));
        return response;
    }

    @GetMapping("/{id}")
    public Map<String, Object> getCustomerById(@PathVariable int id) {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("service", "CUSTOMER-MS");
        response.put("servedByPort", port);
        response.put("id", id);
        response.put("name", "Customer number " + id);
        return response;
    }

    // ---- NEW: this service calls ANOTHER service, by name ----
    // GET /api/customers/with-students
    @GetMapping("/with-students")
    public Map<String, Object> getCustomersWithStudents() {

        // "STUDENT-MS" is a REGISTRY NAME, not a hostname.
        // No port anywhere. Spring resolves it and load balances.
        Object studentData = restTemplate.getForObject(
                "http://STUDENT-MS/api/students", Object.class);

        Map<String, Object> response = new LinkedHashMap<>();
        response.put("service", "CUSTOMER-MS");
        response.put("servedByPort", port);
        response.put("customers", List.of("Tata Motors", "Infosys", "Reliance"));
        response.put("studentServiceSaid", studentData);   // ← nested response
        return response;
    }
}
Expected — GET http://localhost:9393/api/customers/with-students 
{
  "service": "CUSTOMER-MS",
  "servedByPort": "8081",
  "customers": ["Tata Motors", "Infosys", "Reliance"],
  "studentServiceSaid": {
    "service": "STUDENT-MS",
    "servedByPort": "8083",
    "students": ["Amit Shah", "Neha Patel", "Ravi Kumar"]
  }
}
Call it several times and watch the nested servedByPort cycle through 8080, 8082 and 8083 — while the outer one stays 8081. Customer MS is load balancing across Student MS instances, and there is no port number anywhere in the code.
The alternative: OpenFeign The same call, written declaratively — add the OpenFeign dependency and @EnableFeignClients on the main class: 
@FeignClient(name = "STUDENT-MS")
public interface StudentClient {

    @GetMapping("/api/students")
    Object getAllStudents();
}
No implementation — Spring generates it, exactly like a JpaRepository in Session 3. Inject StudentClient and call getAllStudents() as if it were local. Elegant — but be aware it hides the fact that a network call is happening, which is precisely why circuit breakers matter.

▶ 🔧 Troubleshooting Guide
SymptomCauseFix
404 through the gateway, but direct calls work The #1 issue today. Wrong gateway property prefix for your Spring Cloud version — the route block was silently ignored. Switch between spring.cloud.gateway.server.webflux.routes… (2025.0+) and spring.cloud.gateway.routes… (≤2024.0). Confirm with /actuator/gateway/routes.
Gateway won't start, or routing does nothing spring-boot-starter-web is on the gateway's classpath. Remove it. Spring Cloud Gateway is reactive (Netty) and conflicts with the servlet stack.
Service shows as UNKNOWN in Eureka spring.application.name is missing. Set it. It is the registry identity, and what lb:// resolves.
Service never appears in the dashboard Wrong defaultZone, Eureka not running, or you haven't waited. URL must end /eureka/ (trailing slash). Wait 30s and refresh.
Eureka's own log full of Cannot execute request on any known server Missing the two eureka.client.*=false properties on the server. Add register-with-eureka=false and fetch-registry=false.
Port 8080 was already in use An app from Sessions 1–3 is still running. Stop it. lsof -i :8080 (Mac/Linux) or netstat -ano | findstr :8080 (Windows) finds the owner.
All three instances report the same port The --server.port= override didn't take effect. It must be a program argument (not a VM option) with two leading dashes.
servedByPort never changes through the gateway Browser caching, or only one instance registered. Use curl or Postman. Check Eureka shows UP (3). Send at least six requests.
503 Service Unavailable from the gateway The route resolved but no healthy instance was found. Check the service is UP in Eureka, and that the name in lb:// matches exactly (upper case).
NoSuchMethodError / ClassNotFoundException at startup Spring Boot and Spring Cloud versions don't match. Regenerate from Initializr and never hand-edit <spring-cloud.version>.
Cannot resolve @EnableEurekaServer Wrong dependency — Eureka Client instead of Server. The server project needs spring-cloud-starter-netflix-eureka-server.
Everything is slow or the machine is thrashing Six JVMs is a lot of RAM. Drop to two Student instances instead of three — the load balancing lesson still works fine.
